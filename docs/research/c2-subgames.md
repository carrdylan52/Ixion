# ChronicleTwo side games: entry, exit and Ixion hooks

## What this covers

- The side games in ChronicleTwo (Dark Chronicle): fishing, the fish race (Finny Frenzy, `gyorace` and `gyoracesim`), Spheda (`sphida`), the buggy game (`pbuggy`), the camera and photo mode (`photo`), the request memo (`quest`), the aquarium (`menuaqua`), the sub-game dispatcher (`subgame`), medals, and inventing (`inventmn`).
- How each is entered and left, which save data it writes, and what the PC port does with it.
- Which pieces could host cross-game content in Ixion, and which blockers stand in the way.

Basis: read-only review of the `ixion` branch of the ChronicleTwo checkout (HEAD 8d7d7fc8, Kazarov pinned at 3dc38ce). The Kazarov main checkout (9310c53) was read for `PS2_UNIMPLEMENTED`. Nothing was built or run, and no game data was opened. Event scripts are compiled binaries in the disc data, so the script side of each entry point is inferred from the opcodes and not read.

## Key facts

- The sub-game dispatcher has five types: `SUBGAME_NONE`, `FISHING`, `GYORACE`, `BUGGY` and `UNUSED`. Only FISHING, GYORACE and BUGGY have handlers (chronicletwo:ps2/include/subgame.hpp:20-27; chronicletwo:ps2/src/subgame.cpp:120-132).
- `SUBGAME_UNUSED` is a dead slot. Its header comment says it "ends on its first frame", but `sgInitSubGame` never sets `result` for that case, so it returns 0 and clears the running sub-game (chronicletwo:ps2/src/subgame.cpp:111-136). Setting `result = 1` for that case would make it a live slot.
- Only one sub-game runs at a time. The running type and its `SubGameInfo` are file-scope statics (chronicletwo:ps2/src/subgame.cpp:29-50). `SubGameInfo` carries a `CScene *`, a texture-block base and count, and the rod and bait for fishing (chronicletwo:ps2/include/subgame.hpp, `SubGameInfo`, line 54).
- The event-script entry point is opcode 557, `_GOTO_SUBGAME`, which builds a `SubGameInfo` from `EventScene` and calls `sgInitSubGame` (chronicletwo:ps2/src/event_func.cpp:7698-7704; chronicletwo:ps2/include/event_func.hpp:387). Opcode 509, `_GOTO_MENU`, opens any main-menu mode by number (chronicletwo:ps2/src/event_func.cpp:6372-6385).
- Fishing has three entry paths: closing the main menu with a fishing rod in Max's melee slot (chronicletwo:ps2/src/menumain.cpp:1365-1368), the town loop's `MENU_END_FISHING` branch (chronicletwo:ps2/src/editloop.cpp:1340-1361), and the dungeon loop's branch (chronicletwo:ps2/src/dng_main.cpp:1091-1108). The debug menu can also start any sub-game (chronicletwo:ps2/src/editdebug.cpp:378-381).
- Equipping a rod swaps out the melee weapon and remembers it as the pre-equip weapon (chronicletwo:ps2/src/menusys.cpp:1766-1775). `ReEquipFishingGameWeapon` restores it (chronicletwo:ps2/src/userdata.cpp:357-363).
- Rod equipping is gated by `CheckFishCondition`, which blocks maps 0x7D, 0x63 and 0x5F, and in a dungeon requires the floor's battle to be clear (chronicletwo:ps2/src/menusys.cpp:2505-2530).
- Fishing ends in one of four ways: a map event touched during casting (chronicletwo:ps2/src/fishing.cpp:2190-2200), a casting-point event (chronicletwo:ps2/src/fishing.cpp:3066), a town event 201 run when Max crosses a set line on the town map (chronicletwo:ps2/src/editloop.cpp:1210-1224), or a menu close with an end code other than `MENU_END_FISHING` (chronicletwo:ps2/src/editloop.cpp:1318-1319; chronicletwo:ps2/src/dng_main.cpp:1087-1088). Leaving a dungeon breaks any running sub-game (chronicletwo:ps2/src/dng_main.cpp:1143).
- A landed fish is stored by `CUserDataManager::GetFishInAquarium`, which randomises its stats (chronicletwo:ps2/src/userdata.cpp:3842-3870). Fishing points go to the equipped rod through `AddFusionPoint`, not to a wallet (chronicletwo:ps2/src/userdata.cpp:3927-3933). The catch also updates the fish record (chronicletwo:ps2/src/fishing.cpp:3446-3448; chronicletwo:ps2/src/userdata.cpp:3889).
- The fish table has 19 entries (chronicletwo:ps2/src/fishing.cpp:112). Fish items are numbered 310 to 336 (chronicletwo:ps2/include/fishing.hpp, `FISH_ITEM_ID`). Fish places come from `sg/fish/fishing.cfg`, and a background pack `sg/fish/fishing2*.pak` is streamed in beside them (chronicletwo:ps2/src/fishing.cpp:1398-1407).
- The fish race (`gyorace`) is entered by opcode 557 with type 2, or from the Finny Frenzy menu (`MENU_OPEN_GYORACE`, chronicletwo:ps2/src/menumain.cpp:1277-1281). Its six entrants come from the player's own fish, chosen in the menu, and from `sg/gyo/rfd%d.cfg`, which holds four race classes (chronicletwo:ps2/src/menuaqua.cpp:7045-7070; chronicletwo:ps2/include/menuaqua.hpp:1180-1200).
- The race simulation, `gyoracesim`, includes only `common.h`, `mw_runtime.h`, `crandom.hpp` and its own header. It has no scene or save dependency. When the race seed is zero, the seed is hashed from the entrants' stats and tactics (chronicletwo:ps2/src/gyoracesim.cpp:118-136). The whole race is therefore deterministic from its inputs.
- The PC port replaces the race loop with an abort stub. `port/src/gyorace.cpp` defines `PORT_OVERRIDE int sgLoopGyoRace` as `PS2_UNIMPLEMENTED()` (chronicletwo:port/src/gyorace.cpp:5-7). The stub calls `Ps2Unimplemented`, which prints and calls `std::abort()` (kazarov:src/cpp/sce/unimplemented.cpp:6-9; kazarov:include/kazarov/port.h:11). The project's own docs record this: the stub inventory lists it (chronicletwo:docs/port/stubs.md:13, 32), the PC notes name it as the one game stub reached from the executable (chronicletwo:docs/PC.md:1070), and the debug notes list it under PC gaps (chronicletwo:docs/DEBUG.md:92).
- The race loop is `sgLoopGyoRace`, which `sgLoopSubGame` calls every frame. The stub therefore fires on the first race frame after `sgInitGyoRace` has finished loading. Any Finny Frenzy path on PC reaches it, including the bonus race (inference from the call chain; the event scripts were not read) (unverified).
- The race ends in `GYORACE_MODE_END`. That stores the placings and goal times, writes the win and placement flags, and runs event 350 (normal) or 352 (bonus) (chronicletwo:ps2/src/gyorace.cpp:1047-1090; chronicletwo:ps2/src/menuaqua.cpp:6916-6967).
- Spheda is a per-floor game, not a sub-game slot. Its state lives in the `CSphida` object, which the event system allocates in a scene stack slot and points a global at (chronicletwo:ps2/src/event_func.cpp:15653-15712; chronicletwo:ps2/include/sphida.hpp, `Sphida`). It is stepped from the dungeon loop and from the event step (chronicletwo:ps2/src/dng_main.cpp:2275-2288; chronicletwo:ps2/src/event_func.cpp:3254-3267).
- Spheda's event numbers are 3000 (shot at the ball), 3001 (menu near the ball), 3002 (near the ball with fewer than two shots of par) and 3003 (menu away from the ball in a bonus course) (chronicletwo:ps2/include/sphida.hpp, `SphidaEvent`).
- Spheda has three course setups: a random floor course (`SetUp`), a fixed story hole (`s17_SetUp`) and nine bonus courses (`Omake_SetUp`, cases 0 to 8). The event picks the variant with `EVENT_SPHIDA_SETUP_*` (chronicletwo:ps2/src/sphida.cpp:261-512; chronicletwo:ps2/include/event_func.hpp:1045-1047).
- The random course depends on the dungeon scene and its services: `DngMainScene`, the navigation map (`AutoMapGen`), `RandomCircle`, treasure boxes, map event parts and collision (chronicletwo:ps2/src/sphida.cpp:261-365). The par comes from navigation distance on some stage ids (0, 3 to 6) and straight-line distance otherwise (chronicletwo:ps2/src/sphida.cpp:330-352).
- Spheda rewards are a floor table. `GetSphedaPrize` reads `spheda_prize_item` and `spheda_prize_num` from the floor's `DNGMAP_ROOM_INFO`, clamping a rank above `DNGMAP_SPHEDA_PRIZE_NUM - 1` down to that index and returning false for a negative rank (chronicletwo:ps2/src/dngfloor.cpp:459-493; chronicletwo:ps2/src/event_func.cpp:16250-16278). A floor offers Spheda and fishing through `IsPlaySubGame`, which reads the floor's `fishing` and `spheda` flags (chronicletwo:ps2/src/dngfloor.cpp:495-508).
- Spheda scores are kept in `CSphidaData`: a 64-entry table of named scores, nine holes per round, and a password key (chronicletwo:ps2/include/savedata.hpp:96, 511-545; chronicletwo:ps2/src/savedata.cpp:371-405).
- The buggy game (`pbuggy`) is sub-game type 3. It has no caller in the C++ source other than the dispatcher, so it can only be started from event scripts (chronicletwo:ps2/src/subgame.cpp:127-128). It is a defence game in which the player's buggy shoots and bombs at the attackers of a train. Its health counters start at `BuggyHP = 3` and `TrainHP = 1.0` (chronicletwo:ps2/src/pbuggy.cpp:1107-1118).
- The buggy game ends only through two failure events: 0x1F6 when the train runs out of health, and 0x1F7 when the buggy does (chronicletwo:ps2/src/pbuggy.cpp:615-677). The success path was not found in this file.
- Photo mode is entered in two ways. In a dungeon, Max presses Square with a camera in the active item slots (chronicletwo:ps2/src/dng_main.cpp:2352-2384). In a town, the eye view with R2 and Square starts photo mode (chronicletwo:ps2/src/editctrl.cpp:1140-1200). The dungeon check requires `chr_no == USER_CHARA_MAX`, which is Max (chronicletwo:ps2/include/userdata.hpp:20-24).
- A photo is a `USER_PICTURE_INFO` record with a map, a townsperson, a monster, and an idea or scoop number. Thirty slots are kept, each with 64 by 64 packed 16-bit pixels (chronicletwo:ps2/include/userdata.hpp:783-799, 889-898).
- A photo's title is found in order: picture-name table by idea number, then townsperson name, then monster name, then map name (chronicletwo:ps2/src/inventmn.cpp:1475-1500; chronicletwo:ps2/src/inventmn.cpp:1527-1545).
- Photos teach ideas. `CheckPhotoFlag` learns the idea each carried photo shows (chronicletwo:ps2/src/inventmn.cpp:214, 1366). An invention recipe is three idea numbers that make one item (chronicletwo:ps2/include/inventmn.hpp:483-500, 563-640), and `CheckInventItem` checks that the player holds the three (chronicletwo:ps2/src/inventmn.cpp:1838).
- The recipe loader has a PC override that measures and then reads the recipe script into an arena (chronicletwo:port/src/inventmn.cpp:54-89).
- Medals (`yarikomi_medal`) are an `s16` clamped to 0 to 999 (chronicletwo:ps2/src/userdata.cpp:4299-4316; chronicletwo:ps2/include/userdata.hpp:1169). They are earned on the first fast-destroy clear (chronicletwo:ps2/src/dngfloor.cpp:579), a first practice clear (chronicletwo:ps2/src/dngfloor.cpp:721-733), a first fishing record on a floor (chronicletwo:ps2/src/dngfloor.cpp:1174-1226), and by event opcode 1250 (chronicletwo:ps2/src/event_func.cpp:20566-20582).
- Medals are a shop currency. Shop 0x20 charges them, and shop 0x21 is the free goods of Donny (chronicletwo:ps2/src/menushop.cpp:480-512, 537-549; chronicletwo:ps2/include/menushop.hpp:27-30).
- The request memo has two modes, quests and scoops, loaded from `quest%d.cfg` in a pack (chronicletwo:ps2/src/menushop.cpp:2044-2053). Progress is per request id in `CQuestData`, which holds 0x40 entries with accepted and cleared bytes (chronicletwo:ps2/include/quest.hpp, `QUEST_LIMIT`, `QUEST_PLAY_DATA`).
- The aquarium holds three tanks: six first-tank slots, four second-tank slots and two breeding slots (chronicletwo:ps2/include/userdata.hpp:490-505). The aquarium screen is `CAquarium`, which simulates the fish and combines them (chronicletwo:ps2/src/menuaqua.cpp:3635-3692, 4220). It opens from the item menu's aquarium sub-menu and from `MENU_MODE_AQUA` (chronicletwo:ps2/src/menusys.cpp:11974-11977; chronicletwo:ps2/src/menumain.cpp:1583-1584).
- Sub-game save data lives in its own file. `CSubGameData` holds the Spheda table, the fish-race roster (64 entries) and an unlock bitmask (chronicletwo:ps2/include/savedata.hpp:683-760). It is sized separately on the memory card (chronicletwo:ps2/src/memcard.cpp:375-381) and loaded beside the main save (chronicletwo:ps2/src/mainloop.cpp:592-593).
- Extras unlock through main-save flags. `SAVE_FLAG_FINNY_FRENZY_UNLOCKED` enables the race extra. `SAVE_FLAG_COSTUME_UNLOCK` enables the dungeon extra and the costume (chronicletwo:ps2/src/memcard.cpp:1040-1057; chronicletwo:ps2/include/savedata.hpp:122-134).
- An extra starts through `InitOmakeEnv`, which sets `OmakeFlag`, grants items with `DebugGetItem`, and picks a start map and event. The race extra starts at map i03h04, event 100, town loop. The dungeon extra starts at event 6000 in the dungeon loop (chronicletwo:ps2/src/title.cpp:570-589, 1138-1162).
- `CFishingTournament` holds up to ten entries and a rank, and `CFishingRecord` holds 24 records keyed by fish (chronicletwo:ps2/include/userdata.hpp:606-760).
- `fishingobj` is the tackle simulation: point masses, distance constraints and buoyancy for a float, a hook or a lure. Only `fishing.cpp` includes it (chronicletwo:ps2/include/fishingobj.hpp:1-200; chronicletwo:ps2/src/fishing.cpp).

## How it works

### Dispatcher

`sgInitSubGame(type, info)` copies the info, takes the scene's texture block base and count, and calls the type's init. A zero result returns the dispatcher to `SUBGAME_NONE`. Each frame, `sgLoopSubGame` calls the type's loop, and a non-zero return ends the sub-game. `sgExitSubGame` and `sgBreakSubGame` end it early, and `sgRestartSubGame` re-enters the running fishing game with new parameters (chronicletwo:ps2/src/subgame.cpp:104-250).

The dispatcher has eleven dispatch sites (ten switches and one type test in `sgDrawSubGameMap`, which draws only for the race; chronicletwo:ps2/src/subgame.cpp:257). Adding a type means editing each of them (inference from the layout).

Sub-game characters live in scene slots `0x40` to `0x67`, and the effect slot is 7 (chronicletwo:ps2/include/subgame.hpp:43-47). Buggy uses slots `0x40` to `0x46` (chronicletwo:ps2/src/pbuggy.cpp, `BuggySceneChara`). Fishing and the race reserve texture blocks by base and count. The dungeon fishing entry sets the base to 40 and the count to 31 (chronicletwo:ps2/src/dng_main.cpp:1094-1095).

### Fishing

The player equips a rod, and the menu's close event calls `sgInitSubGame(SUBGAME_FISHING)` with the rod and bait numbers. If the same rod is already in play, `sgRestartSubGame` runs instead (chronicletwo:ps2/src/editloop.cpp:1340-1361; chronicletwo:ps2/src/dng_main.cpp:1091-1108). `sgInitFishing` sets up the texture blocks and the read buffers, then the loop runs a loading phase, a camera fade and a casting-point selection. The fishing state machine has casting, bite-wait, battle, failure and success steps (chronicletwo:ps2/include/fishing.hpp, `FISHING_CHARA_MODE`; chronicletwo:ps2/src/fishing.cpp:1628-1745). Menus are closed during the sub-game except in the control step (chronicletwo:ps2/src/fishing.cpp, `sgSetMenuOpenEnableFlag` calls in `sgLoopFishing`).

A bite picks a fish from the appearance table for the position, weighted by bait and time of day (chronicletwo:ps2/src/fishing.cpp:4165-4198; chronicletwo:ps2/include/fishing.hpp, `FISH_PLACE_MAP`). The catch is stored, then the fishing points and the record are updated. In a dungeon with a record check, the floor's fishing record can award a medal (chronicletwo:ps2/src/fishing.cpp:3578-3580).

### Fish race

The race reads the player's chosen fish and fills the other five lanes from the class table. Class and race number come from the event through `_SET_GYORACE_ETC` (chronicletwo:ps2/src/event_func.cpp:7712-7770). Each entrant is turned into a `grFISH_PARAM` from breeding data: power, stamina, three top speeds, tactics and affinity (chronicletwo:ps2/src/gyorace.cpp:428-570). `grGyoRaceSimulate` runs the whole race into per-step progress records, and the display reads them back at the race clock (chronicletwo:ps2/src/gyorace.cpp:586-600; chronicletwo:ps2/include/gyoracesim.hpp). The loop walks `GYORACE_MODE_READY`, `GATE_OPEN`, `RACE`, `FINISH`, `GOAL_VIEW` and `END` (chronicletwo:ps2/include/gyorace.hpp:21-31).

### Spheda

The event system spawns a `CSphida` with one of three setups. `CSphida::Step` checks for the player within 40 units of the ball and offers the shot event, and within 160 units of the ball it offers the menu event. The shot uses a power gauge with states idle, start, charge, charge-set, impact and judge (chronicletwo:ps2/src/sphida.cpp:513-615; chronicletwo:ps2/include/sphida.hpp, `CPowGage`). The events themselves run scripts, which set the club, the score and the next hole through the `_SPHIDA_*` opcodes (chronicletwo:ps2/include/event_func.hpp:523-561). Scores are written to `CSphidaData` by `_SPHIDA_SET_SCORE` (chronicletwo:ps2/src/event_func.cpp:16376-16398). The floor award is read through `GetSphedaPrize`.

### Buggy

`sgInitBuggy` loads the buggy, its passengers, the bomb, the Starbull model, the gun effects and a voice stream (chronicletwo:ps2/src/pbuggy.cpp:374-584). Each frame, `sgLoopBuggy` runs the player's control, the bomb, the buggy and the bomb effects, then steps the characters. Damage to the train and to the buggy is applied in the control code (chronicletwo:ps2/src/pbuggy.cpp:1244, 1641). When either health counter drops to zero, a fade starts and the matching event runs. `sgExitBuggy` then frees the sub-game's characters and effect and stops its music (chronicletwo:ps2/src/pbuggy.cpp:585-613).

### Photo and inventing

Camera mode is a small state machine in `photo.cpp`: off, aim, shutter, after-shot, store and open-menu (chronicletwo:ps2/include/photo.hpp, `TakePhotoState`). Aiming adjusts the projection with the right stick and needs a free photo slot to fire (chronicletwo:ps2/src/photo.cpp:232-270). The store step fills the next free slot with the frame and the subject. `SetTookPhotoData` names the photo, counts the shot and shows the level-up message when it applies (chronicletwo:ps2/src/photo.cpp:549-563). The PC override reads the colour target of the work texture and requests a depth capture on the shutter frame, so the following store step receives the shot (chronicletwo:port/src/photo.cpp:13-48).

The invention menu (`MENU_OPEN_INVENT`) is opened from camera mode by the menu button, in both the dungeon and the town (chronicletwo:ps2/src/dng_main.cpp:2331-2333; chronicletwo:ps2/src/editloop.cpp:1674-1679). From there the player puts three ideas on the board. `CheckInventEnable` returns the item when the three ideas match a recipe, and `HowMuchZairyouMakeItem` and `DeleteUserUsedItem` handle the materials (chronicletwo:ps2/include/inventmn.hpp:563-640).

### Medals, aquarium and requests

Medals are a counter with a shop mode. The shop's `CheckMoney` and `AddMoney` pick the currency by mode, and mode 2 is the medal (chronicletwo:ps2/src/menushop.cpp:480-512). The aquarium is a separate menu over `CFishAquarium`. Fish from the rod go to the first free slot, or to the aquarium item if one is held (chronicletwo:ps2/src/userdata.cpp:3842-3870). The request memo reads `quest%d.cfg` for titles, comments and reaction text, and progress comes from `QuestRequestSetFlag` and `QuestRequestClear` (chronicletwo:ps2/src/quest.cpp:139-228; chronicletwo:ps2/src/event_func.cpp:8500-8535).

## Ixion hooks

- **subgame.cpp dispatch (`sgInitSubGame`, lines 104-139).** Setting `result = 1` for `SUBGAME_UNUSED` gives Ixion a free slot for its own mini-game with no new enum value. The cost is eleven dispatch sites to fill, covering init, loop, second loop, exit, restart, break, map, shadow, character, effect and system draw (inference from the layout).
- **event opcode 557 (`_GOTO_SUBGAME`, event_func.cpp:7698-7704).** A station's event script can start any type by number. This is the cleanest scripted entry for a station game and needs no menu change.
- **Finny Frenzy stub (port/src/gyorace.cpp:5-7).** Replacing this one stub with a real loop is the cheapest route to a playable race on PC. The PC notes already describe a retail-bridge pattern for wrapping a retail body (chronicletwo:docs/PC.md:1003-1005). Until then, any Ixion design that depends on the race is blocked on PC.
- **gyoracesim (pure simulation).** Because the race needs no scene and is deterministic from its entrants, Ixion can run a race outside the game, log the placings, and feed them back through `_SET_GYORACE_ETC`. Outside Dark Chronicle's fish, Ixion can build `grFISH_PARAM` rows from any creature with power, stamina, speed and tactics values (chronicletwo:ps2/src/gyorace.cpp:528-570).
- **sg/gyo/rfd%d.cfg (class roster, menuaqua.cpp:7045).** A data-only crossover: extra fish in the class lists. It needs the fish models, which are a separate asset question (see the risks).
- **GetSphedaPrize (dngfloor.cpp:459-493).** The floor's prize table is the reward source. An Ixion floor can point Spheda's reward at Atla or ABS items by changing the table or by overriding the lookup, without touching the Spheda code.
- **IsPlaySubGame (dngfloor.cpp:495-508).** A floor offers Spheda or fishing from two flags. An Ixion station can use the same flags to offer a game on a floor from the other world.
- **Spheda fixed courses (`s17_SetUp`, `Omake_SetUp`).** These courses set fixed pin and ball positions, a par, and the pin and ball colours (`s17_SetUp` and `Omake_SetUp`, sphida.cpp:367-511). They do not call the random-course services (treasure boxes, `RandomCircle`, map event parts, floor collision). They do still load the red-mark model and build the status sprite, and `Omake_SetUp` calls `AutoMapGen.MinimapAllVisible()`, so the minimap and those models are dependencies too. For a Dark Cloud floor, a fixed course is the smallest possible Spheda (inference from the code; the dependency list is unverified beyond these calls).
- **CSubGameData (savedata.hpp:747-760).** Ixion's own sub-game records can live in the bonus file, which is already separate from the main save and has its own memory-card size. This keeps Ixion progress out of the main save.
- **Medals (userdata.cpp:4299; menushop.cpp:480-512).** Medals are a cross-world currency candidate. Adding a medal source or a medal shop is a data change, and event opcode 1250 already gives a script path into the counter.
- **Photo records (userdata.hpp:783-799; photo.cpp:232-270).** A photo is a 64 by 64 packed 16-bit image with subject numbers. A Dark Cloud picture can be stored in the same record shape. Its subject numbers must map to Dark Chronicle idea, townsperson, monster or map numbers to get a name (chronicletwo:ps2/src/inventmn.cpp:1475-1500).
- **Idea learning (`CheckPhotoFlag`, inventmn.cpp:214, 1366).** A photo can teach an idea. A mapping from a Dark Cloud picture to a Dark Chronicle idea number would make a picture a Dark Chronicle invention source.
- **Recipe loader (port/src/inventmn.cpp:54-89).** The recipe table is loaded from a script at run time, so Ixion can load extra recipes that name Dark Cloud items as outputs.
- **Extras boot (`InitOmakeEnv`, title.cpp:570-589).** The extras boot sets the omake flag, grants items, and picks a map, event and loop. It is a template for an Ixion entry scene.
- **Buggy (pbuggy.cpp).** A train-defence game with its own events is a natural fit for the Ixion train. It is a candidate for a new type, though the success path first needs to be found.

## Risks and blockers

- **Finny Frenzy aborts on PC.** The race loop is an abort stub (chronicletwo:port/src/gyorace.cpp:5-7). Any content that relies on the race is blocked until that stub is replaced. The design draft lists the race as idea 9 with tier T2 (chronicletwo:ixion/docs/DESIGN.md:295). That estimate does not count the stub, and the design also treats the race as unverified (chronicletwo:ixion/docs/design/wacky-max.md:78-80). Both need correcting.
- **Spheda is not self-contained.** The design calls it "self-contained enough to read as a sub-game" (chronicletwo:ixion/docs/design/wacky-max.md:132-134) and it is listed as T2, which the design's own tier definition describes as "a self-contained sub-game module" (chronicletwo:ixion/docs/DESIGN.md:278, 294). The random course, the par, the reward and the events depend on the dungeon scene, the navigation map, the random-circle service, treasure boxes, map event parts, the status bar, the voice unit and the floor manager (chronicletwo:ps2/src/sphida.cpp:261-365; chronicletwo:ps2/src/dngfloor.cpp:459-493). Only the fixed-course setups avoid most of them. The design's claim is wrong for the random course.
- **Design naming drift.** The design names the race class `CGyoRaceData` (wacky-max.md:55). That is the roster in the save file. The race class is `CGyoraceFishData` (chronicletwo:ps2/include/menuaqua.hpp:1180). The design's "fish.hpp (FishInfo)" line refers to Dark Cloud's tree, which is outside this review.
- **The buggy game has no success path in its loop.** Only the two failure events end it (chronicletwo:ps2/src/pbuggy.cpp:615-677). Either the success path lives elsewhere or the buggy game has no win state. This must be found before the game is used.
- **Event scripts were not read.** The entry points into the buggy game, the race and Spheda are all script calls. Which numbers start which games, and where, is therefore not verified here.
- **Sub-game state is global and single-slot.** Spheda, the race, fishing and the buggy game share file-scope statics. A second game started while one runs would corrupt the first. The dispatcher prevents that for sub-games, but Spheda is outside the dispatcher (chronicletwo:ps2/src/event_func.cpp:15689-15690).
- **Character slot overlap.** Sub-games reserve scene character slots from `0x40` (chronicletwo:ps2/include/subgame.hpp:43-47). Buggy and the race use the same range, so an Ixion game must not assume it has the slots to itself.
- **Texture blocks are fixed numbers.** The dungeon fishing entry hard-codes texture block 40 with count 31 (chronicletwo:ps2/src/dng_main.cpp:1094-1095). An Ixion game that uses the same blocks would conflict.
- **Quest progress has 64 slots.** `QUEST_PLAY_DATA_MAX` is 0x40 (chronicletwo:ps2/include/quest.hpp, `QUEST_LIMIT`). Adding Dark Cloud requests to the same table would need a bigger record or a separate table.
- **Photos and medals have fixed caps.** Thirty photos (chronicletwo:ps2/include/userdata.hpp:894), 64 by 64 pixels each (line 898), and medals up to 999 (chronicletwo:ps2/src/userdata.cpp:4307-4309).
- **Pre-equip weapon is a global.** `FishGamePreEquip` holds the weapon taken off for the rod. If the game exits without `ReEquipFishingGameWeapon` running, the weapon is lost (inference from the global; not tested).
- **Unguarded pointer in the race ranking.** `SetGyoRaceRanking` writes `fish->data.fish.race_placement_flags` before checking `fish != NULL` (chronicletwo:ps2/src/menuaqua.cpp:6930-6936). The race path normally sets the fish, so this is unlikely to fire.
- **Bonus reset passes a magic value.** The race reset calls `InitOmakeEnv(next, NULL, NULL)` with `next` set to `GYORACE_MENU_MAIN` (value 1), which equals `OMAKE_TYPE_GYORACE` (chronicletwo:ps2/src/menuaqua.cpp:8060; chronicletwo:ps2/include/title.hpp:230-231). The reset therefore works by coincidence of values, and it also grants items again.
- **Fish models for the race.** `fish_name` lists eighteen character files (chronicletwo:ps2/src/gyorace.cpp:101-120). Any Dark Cloud creature in the race needs a model in one of those formats, which is an asset conversion (T3 in the design's own terms).

- Does the bonus race extra reach the stub on PC? The call chain says yes, but the event path (event 100 in the i03h04 town) was not read.

- Does a Spheda medal reward come only from scripts through opcode 1250, or is there a C++ path? Only the script route was found.
