# ChronicleTwo (DC2): dungeons, floors, sub-games and the --jump dungeon path

## What this covers

ChronicleTwo's (Dark Chronicle, repo "ChronicleTwo") dungeon layer as of the ixion branch head 8d7d7fc8:

- the dungeon main loop and per-frame modes (`dng_main`), floor objects and events (`dng_object`, `dng_event`), status and HUD (`dng_status`, `dng_hud`), and the dungeon effects (`dng_effect`);
- the floor graph: the tree map script data, the floor manager (`dngfloor`), and the tree-map and world-map menus (`dngmenu`, `menumap`);
- the automap generator (`automap`) and the debug window (`dng_debug`);
- the dungeon save part (`savedatadungeon`, `CSaveDataDungeon`, `DNG_FLOOR_SAVE`);
- the dungeon roster and internal IDs, floor flags, geostones, medal ("yarikomi") challenges, practice and fast-destroy conditions, and Spheda (`sphida`);
- the port's `--jump dungeon:<n>[:<floor>]` path, end to end, including the event-based and opening variants.

Counts marked "counted from data" come from a one-off read of the extracted PAL text scripts (`menu/dngmap/dmapN.cfg`, `dflrN.cfg`, `menu/1/flrtitleN.txt`, `menu/1/wldmap.cfg`, `event/view_pal.txt`). They are not checked against the running game.

- **Floor progress flags.** `DNG_FLOOR_FLAG` bits: OPEN 0x1, CLEAR 0x2, PRACTICE_CLEAR 0x8, FAST_DESTROY_CLEAR 0x10, FISHING_CLEAR 0x20, TALK_MONSTER 0x40, SPHEDA_CLEAR 0x80, GEOSTONE_FOUND 0x100, GEOSTONE_READ 0x200, SEAL_CLEAR 0x400 (`chronicletwo:ps2/include/savedatadungeon.hpp:24-37`).
- **Floor graph source data.** Each dungeon has a tree-map script (`menu/dngmap/dmapN.cfg`: `TREE_INFO`, `GI`, `RT`, `RI`, `RI_LINK`, `RI_OP`, `RI_TEX`, `RI_KEYROOM`), a floor-property script (`dflrN.cfg`: `RF_INFO`, `RF_INFO2`), and a title file (`flrtitleN.txt`: `RI_TITLE`). Tags are bound in `chronicletwo:ps2/src/dngfloor.cpp:112-124` (handlers from `:147`) and loaded in `LoadDataTable` (`:393-431`).
- **Floor counts (counted from data).** 160 room cells across the seven grids (9, 16, 24, 21, 23, 28, 39). Room flags from `RI_OP`: 7 start (one per dungeon, floor 0), 19 sub, 6 boss (dungeons 0, 1, 3, 4, 5, 6; none in dungeon 2), 1 exit (dungeon 0, floor 8).

Geostones per dungeon: 0, 8, 18, 14, 16, 18, 0 (unverified). The Channel (dungeon 0) and Palm Brinks (dungeon 6) have no geostones (unverified).

Dungeon 0 has a title for floor 9 that is outside the save table and the grid. Dungeon 2 has a property row for floor 24 with no room. Dungeon 3 has a title for floor 21 with no room. Dungeon 1 has a special floor 100 (`DNGMAP_FLOOR_SPECIAL`), outside the grid (`chronicletwo:ps2/include/dngfloor.hpp:136`).
- **Opening uses out-of-table floors.** The Monica opening runs in dungeon 0 on floor 20 with event 1010, and four `view_pal.txt` rows for dungeon 0 use floors 20 and 21 (counted from data). The save table has only 9 records for dungeon 0, so these floors have no record (`chronicletwo:ps2/src/title.cpp:1029-1031`; `chronicletwo:port/src/test_hooks.cpp:199-211`).
- **Floor 0 is the way out.** Floor 0 of each dungeon is the entrance/exit to a town or georama map, from a fixed table of first-floor map names (`chronicletwo:ps2/src/dngmenu.cpp:2721-2728`, `MakeDngTreeMapJumpNo` at `:2730-2764`). Floor 8 in dungeon 0 and floor 6 in dungeon 1 map to other fixed maps (`:2730-2745`).
- **Dungeon-specific hardcodes.** Dungeon 2 floor 8 always answers itself as next floor (`chronicletwo:ps2/src/dngfloor.cpp:1047-1049`). Dungeon 1 floor 100 returns a fixed string, Japanese or English "Wonder Forest" by language (`chronicletwo:ps2/src/dngfloor.cpp:1080-1092`), while the English title file gives row 100 a different title (counted from data). Dungeon 4 floors 17 and up use a different gate key and door key (`chronicletwo:ps2/src/dng_event.cpp:889-903`).
- **Gate and door keys by dungeon.** Gate keys are item IDs 337, 339, 341, 342, 344, 348, 350; door keys 338, 340, none, 343, 346, 349, 351 (`chronicletwo:ps2/src/dng_event.cpp:58-59`).
- **Dungeon sound bank.** `sound = map_no * 1000 + 1601`, plus 1000 for dungeons 5 and 6 (`chronicletwo:ps2/src/dng_main.cpp:460-464`).
- **System event numbers.** Dungeon scripts start by number: FLOOR_START 1000, TREASURE_BOX 1100, RANDOM_CIRCLE 1120, GEOSTONE 1130, MONSTER_TALK 1150, FLOOR_CLEAR 1500, RANDOM_STONE 2500, guide events 2520-2540 (`chronicletwo:ps2/include/dng_main.hpp:90-101`).
- **Main-loop modes.** `DNG_STATUS_MODE`: FIELD 0, MENU 1, EVENT 2, EVENT_EDIT 3, EVENT_MENU 4, EXIT 5 (`chronicletwo:ps2/include/dng_main.hpp:44-51`). Per-frame dispatch is `LoopDungeonMain` (`chronicletwo:ps2/src/dng_main.cpp:983-1060`).
- **Floor clear.** A floor is cleared when no active monster or mimic remains and `battle_clear` is false; the clear fires event 1500 and sets `battle_clear` (`chronicletwo:ps2/src/dng_main.cpp:2862-2880`, inside `IsEventRun` at `:2795`). `AutoSetMonster` clears `battle_clear` again when it spawns monsters (`chronicletwo:ps2/src/dng_event.cpp:2001`).
- **Passage open rule.** A passage between two floors is open only when both floors carry OPEN; the room mark bobs only on OPEN and not CLEAR floors (`chronicletwo:ps2/src/dngfloor.cpp:800-911`, inference from the code's branch structure).
- **Practice conditions.** Seven kinds (`DNGMAP_PRACTICE_TYPE`: TIME, ITEM_ONLY, WEAPON_ONLY, RIDEPOD_ONLY, MONSTER_ONLY, NO_HEAL, NONE). Difficulty 0 allows kinds 0 to 4 and difficulty 1 allows kind 5 only (`chronicletwo:ps2/src/dngfloor.cpp:590-620`, `chronicletwo:ps2/include/dngfloor.hpp:119-130`).
- **Fast destroy.** A floor's clear time is recorded and compared with the floor's target. Elapsed is `(play_time - subject_counter) * 6 / 5`. The first in-target clear gives one medal (`chronicletwo:ps2/src/dngfloor.cpp:555-588`).
- **Medals.** `yarikomi_medal` is clamped to 0..999 (`chronicletwo:ps2/src/userdata.cpp:4299-4311`). Automatic sources: first fast-destroy clear, first practice clear, first fishing record (`chronicletwo:ps2/src/dngfloor.cpp:579`, `:732`, `:1224`). Scripts can add medals (`chronicletwo:ps2/src/event_func.cpp:20566-20580`). Shops accept medals as a currency mode (`chronicletwo:ps2/src/menushop.cpp:489-509`). A debug shortcut in the shop adds one (`:792`).
- **Sphida (spheda).** `CSphida` with a power gauge (`CPowGage`), a pin and a ball placed on the floor, par, and a status panel (`chronicletwo:ps2/include/sphida.hpp:27-79`, `:140-200`). Setup kinds: normal random placement, fixed story hole (`s17`), and nine bonus courses (`Omake_SetUp`, pars 3 to 15) (`chronicletwo:ps2/src/sphida.cpp:261`, `:367`, `:394`; `chronicletwo:ps2/include/event_func.hpp:1045-1047`).
- **Sphida events.** SHOT 3000, NEAR_BALL 3001, NEAR_BALL_LAST 3002, OMAKE_AWAY 3003 (`chronicletwo:ps2/include/sphida.hpp:54-58`). Setup script entry `_SPHIDA_SET_UP` (`chronicletwo:ps2/src/event_func.cpp:15666`). Prizes are per floor and rank: item and count, with rank clamped to 2 (`chronicletwo:ps2/src/dngfloor.cpp:459-495`; `_SPHIDA_GET_PRIZE` at `chronicletwo:ps2/src/event_func.cpp:16253-16280`).
- **Sphida clear count.** `GetCountSphedaClear` counts floors with `spheda_clear` set across all dungeons (`chronicletwo:ps2/src/dngfloor.cpp:1143-1171`).
- **Bonus content.** `OmakeFlag` switches dungeon entry to the `d0N_sfida_<lang>.stb` scripts (`chronicletwo:ps2/src/dng_main.cpp:951-953`).
- **Geostones.** A geostone is placed on the floor at setup only if the floor's geostone flag is set and GEOSTONE_FOUND is not (`chronicletwo:ps2/src/dng_event.cpp:1870-1890`, inside `AutoSetTreasureBox` at `:1683`). Its trigger test is a 30-unit radius around a point 20 units below the stone's position (`chronicletwo:ps2/src/dng_event.cpp:491-506`). Its state is cleared on floor setup (`:2344`).
- **Automap generator.** `CAutoMapGen` builds each floor's grid (`chronicletwo:ps2/include/automap.hpp:92-100`). Floors use a preset cfg (`dungeon/cfg_file/*.cfg`, 48 files in the extracted data) or a random layout, chosen by event script `_LOAD_DUNGEON_MAP_FILE` with a generation flag (`chronicletwo:ps2/src/event_func.cpp:5580-5600`; `chronicletwo:ps2/src/dng_event.cpp:2077`).
- **Preset choice.** In preset mode, the preset index depends on floor ranges (floor 5 always preset 0; floor 11 always preset 0; others random from 1 to 19, or 0 to 9 from floor 19 up) (`chronicletwo:ps2/src/automap.cpp:2285-2318`) (unverified).
- **Map reveal.** The Map item sets `MINIMAP_REVEAL_ROOMS`; the Magic Crystal sets `MINIMAP_REVEAL_SYMBOLS` (`chronicletwo:ps2/src/userdata.cpp:4366-4375`; flags at `chronicletwo:ps2/include/scenesnd.hpp:70-71`).
- **Tree map menu.** `CMenuTreeMap` and `CDngFreeMap` (`chronicletwo:ps2/src/dngmenu.cpp:256-300`, `:2902` for `Step`, `:3943` for `DngTreeMapInit`). It opens from an event (`_GOTO_DNG_MAP`, `chronicletwo:ps2/src/event_func.cpp:5385-5392`, opcode 61), from the in-dungeon menu, or from the world map (`chronicletwo:ps2/src/menumap.cpp:855-860`).
- **World map entries.** `wldmap.cfg` has 30 places; 10 lead into dungeons (LOOP_DUNGEON = 2). Seven of those open the dungeon's tree map (floor -1). Three go straight to a floor: dungeon 2 floors 18 and 8, and dungeon 3 floor 9 (counted from data). Field order: map, loop, area, dungeon, floor, flag, type (`chronicletwo:ps2/src/menumap.cpp:298-325`; `chronicletwo:ps2/include/menumap.hpp:117-128`).
- **Tree-map jump.** The jump action sets the destination floor in `MenuArg.result[2]`, sets the save floor only for SUB and BOSS rooms, and charges about half the money when the player leaves a non-clear floor in the dungeon menu (`chronicletwo:ps2/src/dngmenu.cpp:3290-3300`, `:3400-3436`).
- **Dungeon entry script.** `_GOTO_DNG(map, floor, event)` requests a dungeon loop with an `INIT_LOOP_ARG` (opcode 62, `chronicletwo:ps2/src/event_func.cpp:5397-5416`). `_DNG_SET_FLOOR_ID` and `_DNG_GET_FLOOR_ID` read and write the save floor (`chronicletwo:ps2/src/event_func.cpp:5231-5268`). `_GET_NEXT_FLOOR` returns the next floor on a route type (`:17577-17593`).
- **Dungeon-level state.** `DNG_BATTLE_AREA` holds the battle state, floor manager, minimap reveal, `battle_clear`, practice actions and floor status bits (`chronicletwo:ps2/include/scenesnd.hpp:149-180`). Seal bits are `DNG_FLOOR_STATUS_SEAL_MONICA` 0x1 and `_SEAL_MAX` 0x2 (`:117-118`).
- **Seals.** `IsSealFloor` returns the floor's seal, dropped when SEAL_CLEAR is set and when the seal's character is not in the party (`chronicletwo:ps2/src/dngfloor.cpp:514-552`).
- **Port entry for --jump.** `main.cpp` stores the option (`chronicletwo:port/src/main.cpp:127-128`), `Run` reads `--jump` or `DC2_JUMP` and calls `GameSetJump` (`chronicletwo:port/src/main.cpp:255-258`). The main loop calls `GamePrepareJump` after `LoadGameConfig(NULL)` and before the mode loop (`chronicletwo:port/src/mainloop.cpp:202`), and calls `GameGiveOnArrival` after each mode init (`:260`).
- **Dungeon jump values.** `GameParseJump` accepts `dungeon:<map 0-6>[:<floor 1-99>]`; the default map is 0 and the default floor is 1; floor 0 is rejected, and so is any floor outside the save table (`chronicletwo:port/src/test_hooks.cpp:88-101`). Unit tests cover the boundaries (`chronicletwo:port/src/tests/test_hooks_test.cpp:17-38`).
- **Dungeon jump application.** `GamePrepareJump` sets `DebugFlag = 1`, sets the boot-init flag, runs `InitSaveData`, loads `dbg/cap1.cfg`, and sets `map_no` and `floor_no` (`chronicletwo:port/src/test_hooks.cpp:162-198`). The cap1 config sets PROGRESS 2 and an item set (`dbg/cap1.cfg` in the extracted data).
- **Event jump.** `event:<id>` resolves through `event/view_pal.txt` (0-based tab columns 1 to 3 hold dungeon+1, the floor, and the event ID; column 0 is a name). Event 26010 resolves to dungeon index 1, floor 12 (counted from data; `chronicletwo:port/src/test_hooks.cpp:41-76`). The event path does not range-check the floor against the save table.
- **Debug entry points.** The retail debug menu's Chapter 1 row jumps to dungeon 0 floor 1 with `cap1.cfg`, and its Spheda row jumps to dungeon 2 floor 1 with event 4000 (`chronicletwo:ps2/src/mainloop.cpp:1321-1326`, `:1367-1376`).

## How it works

**Entering a dungeon.** Every entry builds an `INIT_LOOP_ARG` (map, floor, event, memory-card state). `InitDungeonMain` reads it (`chronicletwo:ps2/src/dng_main.cpp:325`). It sets `stage_id` to the dungeon (`:345`), and if `floor_no >= 0` it calls `SetFloorID`, which remembers the previous floor (`:347-349`, `chronicletwo:ps2/src/savedatadungeon.cpp:64-68`). It then loads the floor graph from `dmapN.cfg`, `dflrN.cfg` and the title file (`:422`), creates the party and monster slots (`:393-416`), loads the map sound and BGM (`:460-472`), and calls `EntryEventScript` (`:820`). That loads `map/d/d0N/d0N_<lang>.stb` or the sphida variant (`chronicletwo:ps2/src/dng_main.cpp:943-978`). The event number is the arg's event, or `DNG_EVENT_FLOOR_START` (1000) when it is zero (`:828-832`).

**Per-frame loop.** `LoopDungeonMain` runs `DngMainKey` and `DngStep` in field mode (`chronicletwo:ps2/src/dng_main.cpp:983-1030`). Menu and event modes call the menu or event runner. Interaction checks run in `IsEventRun` (`:2795-2988`), roughly in this order: floor clear, magic-sword guide, random circle, level-up guide, geostone, treasure box, monster talk.

**Floor graph.** `LoadDataTable` runs three tag passes over the scripts (`chronicletwo:ps2/src/dngfloor.cpp:393-431`). `RelationGlid` links grid cells in four directions (`:762-798`). `CheckDrawGlidInfo` recomputes visited flags from the save and sets room marks and passage open state (`:800-911`). `GetNextRoom` and `GetNextGlid` walk a passage from a room to the next room (`:968`, `:912`).

**Tree map.** `DngTreeMapInit` loads the dungeon's map graphics and sets the cursor to the saved floor, reset to 1 when it is below 1 or above the dungeon's maximum floor (`chronicletwo:ps2/src/dngmenu.cpp:3943-4007`, `:2790-2800`, maximum from `maxidtable_2752` at `:2767`). Selecting a room shows its info and a yes/no question. Named rooms (start, sub, exit, boss) get a named question (`chronicletwo:ps2/src/dngmenu.cpp:3286-3320`). On confirm, the menu sets `MENU_END_DNG_MOVE` (`:3414`). On close, the in-dungeon branch can re-route through `MakeDngTreeMapJumpNo` to an edit map (`:2979-2993`).

**Leaving a dungeon.** When the menu returns `MENU_END_DNG_MOVE` with floor 0, the dungeon loop switches to the fixed town map with event 100 and sets DNG_STATUS_EXIT (`chronicletwo:ps2/src/dng_main.cpp:1078-1086`). Start+Select with the debug flag on forces the exit too (`:1133-1134`). The exit path runs `PlayerPartyCure` unless suppressed, clears the seal bits, and terminates events (`:1142-1166`).

**Records and clears.** `visit_count` is read and written by scripts through `_SET_FLOOR_INFO` field 7 and `_GET_FLOOR_INFO` (`chronicletwo:ps2/src/event_func.cpp:17459-17512`; inference that the floor-entry script does the write). Clear, practice, fast-destroy and fishing results write their own bits and medals (see Key facts). `GetFloorInfoPtr` returns NULL outside the table, so callers check it.

**Geostone.** At setup, if the floor has a geostone and it is not yet found, the stone is placed on a flat cell away from the entrance (`chronicletwo:ps2/src/dng_event.cpp:1870-1895`). Standing within 30 units of that point offers event 1130 when the action button is pressed. The found and read bits (`chronicletwo:ps2/include/savedatadungeon.hpp:34-35`) are written through the floor-info script path (`_SET_FLOOR_INFO` field 5 sets bits; inference, the event scripts were not decoded).

**Spheda.** `_SPHIDA_SET_UP` allocates the game and calls one of three setup routines (`chronicletwo:ps2/src/event_func.cpp:15685-15709`). `CSphida::Step` runs each frame when the game is playing; it checks the player is at a run-event point and no other event is active, then starts event 3000 to 3003 near the ball (`chronicletwo:ps2/src/sphida.cpp:513-560`). The gauge goes through start, charge, set, impact and judge (`chronicletwo:ps2/include/sphida.hpp:27-33`). Result codes are on the gauge; scripts read them to decide the stroke.

**Fishing record.** `CheckFishingRecord` compares a catch with the floor's fishing record. A negative test value means "at most", a positive one "at least", and a newly beaten record sets FISHING_CLEAR and gives a medal (`chronicletwo:ps2/src/dngfloor.cpp:1174-1215`; caller `chronicletwo:ps2/src/fishing.cpp:3579`).

**The --jump dungeon path, end to end.**

1. Command line or env: `--jump dungeon:0:1` is stored by `ParseOptions` (`chronicletwo:port/src/main.cpp:127-128`); `DC2_JUMP` is read when the option is absent (`:255`).
2. Validation: `GameSetJump` calls `GameParseJump` (`chronicletwo:port/src/test_hooks.cpp:143-151`). A bad value triggers `Usage` and exit (`chronicletwo:port/src/main.cpp:257-259`).
3. Boot: the main loop skips the logos and sets English (`chronicletwo:port/src/mainloop.cpp:99-101`), then runs `GamePrepareJump` (`:202`). That sets `DebugFlag = 1` and the boot-init flag, clears the arg, calls `InitSaveData`, loads `dbg/cap1.cfg`, and sets `map_no` and `floor_no` (`chronicletwo:port/src/test_hooks.cpp:162-198`).
4. Entry: `LoopInit[LOOP_DUNGEON]` runs `InitDungeonMain` with that arg (`chronicletwo:port/src/mainloop.cpp:259`). The floor is set with `SetFloorID` (`chronicletwo:ps2/src/dng_main.cpp:347-349`), the floor graph loads, and the floor-start event (1000) runs.
5. Gifts: `--give` items are added on arrival (`chronicletwo:port/src/test_hooks.cpp:221-236`; `chronicletwo:port/src/mainloop.cpp:260`).

Other jump modes: `opening` uses floor 20 and event 1010 in dungeon 0, matching the retail title's new-game entry (`chronicletwo:port/src/test_hooks.cpp:199-211`; `chronicletwo:ps2/src/title.cpp:1029-1032`); `event:<id>` reads the view table (`chronicletwo:port/src/test_hooks.cpp:41-76`); `title` and `menu` do not enter a dungeon.

**Port-side dungeon overrides.** Most dungeon retail code is compiled unchanged. Native replacements are tagged `PORT_OVERRIDE` in `chronicletwo:port/src/`: status bar (`dng_status.cpp`), HUD warnings and lock-on (`dng_hud.cpp`), damage numbers (`dng_damage.cpp`), pickups (`dng_pickup.cpp`), enemy life gauges and lock-on text (`dng_target.cpp`), rocket and laser managers (`dng_object.cpp`), monster load and red marker (`dng_event.cpp`), minimap symbols (`automap.cpp`), eye view reset (`dungeon_eye.cpp`), and the base character stacks (`dng_main.cpp`). Port-only dungeon camera code lives in `first_person_walk.cpp`, `camera_mouse.cpp` and `camera_zoom.cpp`.

## Ixion hooks

- **Canonical dungeon key.** Use dungeon index 0 to 6 and floor id as the cross-world key for dungeon places. Both fields already exist in `WMAP_POS_DATA` (`chronicletwo:ps2/include/menumap.hpp:117-128`) and in `INIT_LOOP_ARG`.
- **Floor entry from another world.** `NextLoop(LOOP_DUNGEON, arg)` with `map_no` and `floor_no` is the script-side path into a floor (`_GOTO_DNG`, `chronicletwo:ps2/src/event_func.cpp:5414-5416`); the debug event browser (`chronicletwo:ps2/src/mapselect.cpp:966`) and the title's new-game path (`chronicletwo:ps2/src/title.cpp:1032`) call it directly, while the tree map and world map end through the menu's move result. `GamePrepareJump`'s dungeon branch (`chronicletwo:port/src/test_hooks.cpp:193-198`) is a working template for a travel entry that bypasses the world map.
- **Travel targets.** The `wldmap.cfg` POS table is where a world-map crossing would add or re-route entries (`chronicletwo:ps2/src/menumap.cpp:298-325`). The tree-map entry is `DngTreeMapInit` with the dungeon index (`chronicletwo:ps2/src/menumap.cpp:855-860`).
- **Exit routing.** `MakeDngTreeMapJumpNo` is where a floor-0 or special floor leaves the dungeon for a town-side map (`chronicletwo:ps2/src/dngmenu.cpp:2730-2764`). An Ixion route for a C1 town would hook here.
- **Floor flags as shared progress.** The OPEN, CLEAR and visit bits are per world. A cross-world rule can read them through `GetFloorInfoPtr` and `_GET_FLOOR_INFO` (`chronicletwo:ps2/src/event_func.cpp:17518-17548`) without changing the record layout.
- **Seal logic already party-aware.** `IsSealFloor` already checks party membership (`chronicletwo:ps2/src/dngfloor.cpp:514-552`). A cross-cast party rule can extend it.
- **Shared currency.** Medals (`yarikomi_medal`, cap 999) work as a shop currency (`chronicletwo:ps2/src/menushop.cpp:489-509`) and are granted by floor records. A medal-linked reward could be shared through `AddYarikomiMedal`.
- **Spheda as a self-contained module.** `CSphida` holds its own state (`chronicletwo:ps2/include/sphida.hpp:140-200`) and is driven by events 3000 to 3003 and a small set of script functions (`chronicletwo:ps2/src/event_func.cpp:15666-16320`). That makes it the cleanest dungeon sub-game to port into a C1 floor (inference from the file structure).
- **Automap presets.** `LoadDungeonMapFile` takes a cfg name and generation flags from script (`chronicletwo:ps2/src/dng_event.cpp:2077-2110`), so an Ixion floor can use a preset from either world's cfg set.
- **Minimap reveal items.** The Map and Magic Crystal reveal flags (`chronicletwo:ps2/src/userdata.cpp:4366-4375`) apply to whatever floor is active, so they carry across worlds without change.

## Risks and blockers

- **Non-dense floor ids.** Title rows, property rows, grid cells and save records do not line up (dungeon 0 floor 9; dungeon 2 floor 24; dungeon 3 floor 21; floors 20 and 21 of dungeon 0 used by the opening). Any Ixion floor table must carry these gaps explicitly. Lookups that assume a floor is in the save table will return NULL (`chronicletwo:ps2/src/savedatadungeon.cpp:15-33`).
- **Duplicated limit tables.** The 9/16/25/21/23/29/39 limits appear in `savedatadungeon.cpp:13` and again as a local array in `CheckDrawGlidInfo` (`chronicletwo:ps2/src/dngfloor.cpp:800-810`). A change to one must change the other.
- **Hardcoded floor cases.** Dungeon 1 floor 100 title (Japanese, or English "Wonder Forest"), dungeon 2 floor 8 next-floor, dungeon 4 gate keys from floor 17, and the floor-0 name table are all in code, not data (see Key facts). A port that moves a dungeon must carry these.
- **Unchecked dungeon pointer.** `IsClearPractice` dereferences the save dungeon pointer without a NULL check (`chronicletwo:ps2/src/dngfloor.cpp:590-594`), unlike its neighbours. Calls from a null-save state would crash.
- **Unbounded placement loops.** `CSphida::SetUp` finds the pin and ball with `do { } while (...)` loops that have no retry limit (`chronicletwo:ps2/src/sphida.cpp:261-300`). A floor with no valid flat cells would hang. By comparison, the random-circle placement in `AutoSetTreasureBox` uses a 100-try cap (`chronicletwo:ps2/src/dng_event.cpp:1846-1866`), while the mimic treasure-box placement `do { } while (!placed)` (`chronicletwo:ps2/src/dng_event.cpp:1820-1827`), the geostone loop (`:1876`), and the sphida loops have no such cap.
- **Event jump is not range-checked.** `ResolveEvent` accepts any floor 0 to 99 and skips the save-table check that `GameParseJump` applies (`chronicletwo:port/src/test_hooks.cpp:62-65`). Four event rows already use out-of-table floors (20 and 21 of dungeon 0); their labels read as opening and prologue sequences (inference), which retail also runs.
- **Floor-to-map binding is not decoded.** The extracted tree has only 24 floor folders across the seven dungeons (`map/d/d0N/fNN`, for example `map/d/d01` has f01 and f09; a few are named differently, such as f01r). The floor-to-map mapping lives in the per-dungeon `.stb` scripts, which were not decoded here.
- **Jump runs are not campaign state.** `--jump` forces `DebugFlag` on (`chronicletwo:port/src/test_hooks.cpp:175`), loads a debug config with PROGRESS 2 (`dbg/cap1.cfg`), and gives the retail debug item set. Debug-gated branches in the dungeon code run during a jump; the dungeon debug window is gated on `DebugFlag` (`chronicletwo:ps2/src/dng_main.cpp:2157`).
- **Fast-destroy units.** The `* 6 / 5` factor in `IsClearMostFastDestroy` is not explained in code. A port that changes the frame rate must keep the same unit.
- **Save-size pinning.** `DNG_FLOOR_SAVE` and `CSaveDataDungeon` are asserted to exact sizes with `PORT_RECORD_ASSERT`. A cross-world save layout that adds fields must bump those records.

## Open questions

- **Does a `--jump dungeon:0:1` run show the floor list?** `docs/DEBUG.md` says `dungeon:0:1` shows the Underground Channel floor list by frame 250 and that the floor argument selects in that list. The code sets the floor directly (`chronicletwo:ps2/src/dng_main.cpp:347-349`) and runs event 1000. Whether the floor-start script opens the tree map (`EVENT_EXT_GOTO_DNG_MAP` = 61, `chronicletwo:ps2/include/event_func.hpp:114`) was not checked in the binary `.stb`. Verify before relying on either reading.
- **Which floor-start events carry a tree map?** The same question for other floors: how many scripts issue `_GOTO_DNG_MAP`?
- **Where is the in-dungeon floor change completed?** The tree-map jump sets `MenuArg.result[2]` and sets the save floor only for SUB and BOSS rooms (`chronicletwo:ps2/src/dngmenu.cpp:3430-3434`). The step that moves a player between two normal floors was not fully traced through the menu end handler (`chronicletwo:ps2/src/menumain.cpp:1355-1380`).
- **Practice difficulty.** `IsClearPractice(difficulty)` takes its value from script (`chronicletwo:ps2/src/event_func.cpp:19450`). What the value means (normal and hard, or mode) is not in code.
- **Dungeon 1 floor 100.** Its role in the story was not traced. The English title row and the hardcoded string disagree (see Risks).
- **Event 26010 naming.** The docs call it the Rainbow Butterfly Wood boss-event arena. The table row resolves to dungeon index 1, floor 12, whose English title is "Chamber of the Sleeping Earth Gem" (counted from data). Confirm which place the docs mean before using it as a fixture.
- **Sphida story hole.** Which floor and script call `s17_SetUp` (`EVENT_SPHIDA_SETUP_S17`) was not traced.
- **Dungeon 2 boss flag.** The parse found no boss-flagged room in dungeon 2 (counted from data). Confirm against the floor script before relying on it.
