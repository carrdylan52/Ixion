# ChronicleTwo (DC2) towns, Georama and villagers

## What this covers

How ChronicleTwo (Dark Chronicle) builds and runs its towns: the town main loop and its walk/edit switch, the five Georama towns and their saved layouts, the map table and the files a town map loads, the world-map travel that brings the player in, the villager roster (villager places, story schedules, and the walking townspeople), the Georama residents who move into houses, and the save fields that hold it all. Interiors and the Palm Brinks sub maps are covered where a town hands off to them. Dungeons, battles and the Dark Cloud side are out of scope except where they feed Georama (geostones, materials).

Citations use `chronicletwo:` for the `c2` checkout (retail `ps2/src` and `ps2/include` unless marked `port/src`). `chronicletwo-data:` means the extracted PAL disc data that the game loads at run time; it is not in the repository. Line numbers are as read in the checked-out tree; they are not re-verified against a build.

## Key facts

- The town loop is one main-loop mode. `EditInit` is the arrival function and `EditMapJump` is the one place an outdoor town map is loaded on arrival (interiors go through `GotoInterior` and `InteriorMapJump` instead) (`chronicletwo:ps2/src/editloop.cpp:548`, `chronicletwo:ps2/src/editloop.cpp:2713`). `EditInit` resolves its argument by name: `EditMapJump(SearchMapNo(GetMapName(arg.map_no, NULL)))` (`chronicletwo:ps2/src/editloop.cpp:877`).
- Other callers of `EditMapJump` are the world-map move (`chronicletwo:ps2/src/editloop.cpp:1362-1379`), a debug jump (`chronicletwo:ps2/src/editloop.cpp:1405-1407`), and the story/event jump (`chronicletwo:ps2/src/editloop.cpp:1554-1555`). No caller checks its return value.
- Five Georama towns, numbered by their map-table index, which is also their `MapNo` and their save slot: index 0 `g01`, 1 `g02`, 2 `g03`, 3 `g04`, 4 `g05` (chronicletwo-data `map/map0.cfg`, MAP_NAME rows 0 to 4, type 1, sel 1). The analysis enum names them, in order, Sharlot, Stera, Benietio, Heim and Moon Flower (`chronicletwo:ps2/include/editanalyze.hpp:23-29`, dispatch at `chronicletwo:ps2/src/editanalyze.cpp:80-106`).
- Map kinds are the `MapType` enum: Georama 1, Georama interior 2, interior 4, future 5, future interior 6 (`chronicletwo:ps2/include/mapselect.hpp:43-49`). Palm Brinks (`m01`, index 10) and its sub maps `m02` to `m05` (indices 11 to 14) are type 3 with selection category 2 ("PalmBlinks", `MapSelType` at `chronicletwo:ps2/include/mapselect.hpp:23-31`), a value the `MapType` enum does not name (`chronicletwo-data map/map0.cfg`). Inference: type 3 is an ordinary exterior.
- Map lookup is positional. `LoadMapName` reads `map/map<lang>.cfg` and fills the table in file order (`chronicletwo:ps2/src/mapselect.cpp:277-294`); `SearchMapNo` finds a record by name (`chronicletwo:ps2/src/mapselect.cpp:385`). The table has 189 records in the language-0 file.
- A town's files are derived from its name: the folder is `map/<c>/<cc>/<name>`, so `g01` loads from `map/g/g01/g01.*` (`chronicletwo:ps2/src/mapselect.cpp:306-325`). Per map: `.map` `.mpk` `.ipk` `.efp` `.sky` and `.cfg` (`chronicletwo:ps2/src/mapjump.cpp:251-300`). The script is `<name>.stb`, with a `_<lang>.stb` override when present (`chronicletwo:ps2/src/mapjump.cpp:372-410`).
- A second, shared asset set is attached through the map record's third name: Georama towns 1 to 4 use `map/cmn/g00/g00` (chronicletwo-data `map/map0.cfg` rows 0 to 3; `chronicletwo:ps2/src/mapjump.cpp:309-318`). Chapter 6 and 7 redirect the train-station add-on from `trn/train` to `trn2/s36` (`chronicletwo:ps2/src/mapjump.cpp:300-306`).
- The Georama edit data is per language. `g0N<lang>.gpi` holds the part definitions and `g0N.cfg` holds the starting parts, rivers and water (`chronicletwo:ps2/src/editloop.cpp:2806-2818`). The extracted data has seven `.gpi` languages per town (`g010` to `g016`), and `geo0.cfg` to `geo6.cfg` hold the analysis scripts, one per language (chronicletwo-data `map/g/g01/`, `geo0.cfg`).
- The analysis script for each language is read at language change, one `GEO_ANALYZE` block per Georama town (five blocks in every `geo<n>.cfg`). The loader names the file with `LanguageCode`, not a map number (`chronicletwo:ps2/src/mainloop.cpp:452`, `chronicletwo:ps2/src/editdata.cpp:908-930`).
- The Georama save slot is `CSaveData::edit_data[SAVE_EDIT_DATA_MAX]` with `SAVE_EDIT_DATA_MAX` 5 (`chronicletwo:ps2/include/savedata.hpp:60`, `chronicletwo:ps2/include/savedata.hpp:231`). Each `CEditData` is 0x5510 bytes and holds no pointers (`chronicletwo:ps2/include/editdata.hpp:446-447`).
- Saving writes only for towns: `EditDataSave` runs when not inside an interior, and stores into `GetEditData(MapNo)`. `GetEditData` returns NULL for an index out of range, so Palm Brinks and the future maps write nothing (`chronicletwo:ps2/src/editloop.cpp:3023-3047`, `chronicletwo:ps2/src/savedata.cpp:155`).
- Placed parts are capped at 300 slots (`chronicletwo:ps2/include/editdata.hpp:56`). `CEditMap::SaveData` calls `exit(0)` when a save would overflow (`chronicletwo:ps2/src/editdata.cpp:156-300`, the "Parts Num Over" branch).
- Future maps `f01` to `f04` (type 5) do not edit a layout. They read the Georama slots 0 to 3 (Sharlot to Heim) through `PartsOnOff` to show or hide their own map parts, and their own save slot lookup returns NULL (`chronicletwo:ps2/src/savedata.cpp:155`, reached from `EditDataSave` at `chronicletwo:ps2/src/editloop.cpp:3023-3047`); `PartsOnOff` is at `chronicletwo:ps2/src/editdata.cpp:659` (`chronicletwo:ps2/src/editloop.cpp:2835-2851` for the slot selection). `f01` loads the `f01_2` variant when Sharlot's analysis flag 3 is unset (`chronicletwo:ps2/src/editloop.cpp:2776-2779`, `chronicletwo:ps2/src/editloop.cpp:2835-2851`; variant files exist as chronicletwo-data `map/f/f01/f01_2.*`).
- The world map is data-driven. `wldmap.cfg` (one copy per numbered folder under `menu/`, which look like language sets) has `POS` rows (name index, map number, loop, area, dungeon, floor, reachable flag, type) and `AREA` rows (`chronicletwo:ps2/include/menumap.hpp:117-150`, parser `chronicletwo:ps2/src/menumap.cpp:239-345`). The five Georama towns are loop 1 rows on areas 2, 3, 4, 5 and 7, with reachable flags 208, 302, 402, 504 and 700 as written in the file (chronicletwo-data `menu/0/wldmap.cfg`, POS rows 4, 9, 15, 20, 25).
- Choosing a non-dungeon place sets `MENU_END_WORLD_MOVE` with the map number in `WorldMap_MapNo` (`chronicletwo:ps2/src/menumap.cpp:789-801`). The town loop burns the Georama parts first, then jumps (`chronicletwo:ps2/src/editloop.cpp:1362-1379`). The s12 place is redirected to s34 when flag 0x2BC is set (`chronicletwo:ps2/src/menumap.cpp:807-808`, `chronicletwo:ps2/include/savedata.hpp:131`).
- The loop state machine is small: walk, edit, walk menu, edit pre-menu, edit menu, wait-for-read (`chronicletwo:ps2/include/editloop.hpp:32-40`). Walk to Georama and back is gated by `CheckWalkToEdit` and `CheckEditToWalk` (`chronicletwo:ps2/src/editloop.cpp:1775-1791`, `chronicletwo:ps2/src/editmode.cpp:3024`, `chronicletwo:ps2/src/editmode.cpp:3080`).
- Build stock is one counter per part kind: `build_parts_num[0x100]` in the save (`chronicletwo:ps2/include/savedata.hpp:46`, `chronicletwo:ps2/include/savedata.hpp:230`). Placing one part spends one (`chronicletwo:ps2/src/editmode.cpp:1047`, `chronicletwo:ps2/src/editmode.cpp:1248`); removal refunds (`chronicletwo:ps2/src/editmode.cpp:1186`) and burning refunds (`chronicletwo:ps2/src/editloop.cpp:2628-2660`).
- Heim's fire burns the Georama parts in the live map when Heim is the current main map, unless flag 0x208 (`SAVE_FLAG_HEIM_FIRE_OUT`) is set (`chronicletwo:ps2/src/editloop.cpp:2628-2660`, `chronicletwo:ps2/include/savedata.hpp:127`, `EDIT_ANALYZE_MAP_HEIM` = 3 at `chronicletwo:ps2/include/editanalyze.hpp:27`). Burnt parts refund stock and evict residents (`LeaveHouse`, `chronicletwo:ps2/src/userdata.cpp:3634`). The burn runs on world move (`chronicletwo:ps2/src/editloop.cpp:1378`), on leaving the loop (`chronicletwo:ps2/src/editloop.cpp:517`), and on the debug jump.
- The town clock is `CScene::time` in hours, mirrored into `CSaveData::now_time` (`chronicletwo:ps2/src/scene.cpp:1820`); it starts at 12.0 (`chronicletwo:ps2/src/savedata.cpp:22`) and does not advance while `time_stop` is set or outside walk control (`chronicletwo:ps2/src/editloop.cpp:1101-1104`). A day counter increments when the clock wraps past 24 (`chronicletwo:ps2/src/scene.cpp:1828-1846`).
- Villagers are placed from two scripts. `place.cfg` holds 158 place blocks, each with a map number and position, and `npc_place4.cfg` holds 11 story progress points (`PROG_INFO`), 141 villager schedules (`NPC`), and 177 model/house records (`NPC_INFO`). Both are loaded by `LoadGameInfo` (`chronicletwo:ps2/src/vlgr_info.cpp:834-863`, tags at `chronicletwo:ps2/src/vlgr_info.cpp:175-225`).
- Villagers appear by map, not by town: the schedule places sit on the Palm Brinks maps (10 to 14), the future maps `f01` to `f04` (maps 25, 26, 82 and 102), the `i` interiors (unverified), and many others, including 22, 23 and 75 and the ranges 27 to 52 and 101 to 156 (`place.cfg`, counted by this research). None sits on one of the five Georama towns (indices 0 to 4). Georama residents come from houses, not from this table (chronicletwo-data `place.cfg`, counted by this research).
- The appearance rule is `CVillagerMngr::GetAppearVlgr(progress, time, map)` (`chronicletwo:ps2/src/villagermngr.cpp:370-489`). `time` is 0 for day and 1 for night, from a 21:00 to 06:00 window (`chronicletwo:ps2/src/scenevillager.cpp:492-505`). Per villager it walks the schedule newest-first and stops at the first entry the current progress has reached (`GAME_PROGRESS_INFO::order`), then takes the place for that time in each of four alternatives.
- The roster is loaded at map entry only: `EditMapJump` calls `LoadVillager(MapNo, 0x4E)` (`chronicletwo:ps2/src/editloop.cpp:2877`), sub maps call `LoadSubVillager` (`chronicletwo:ps2/src/editloop.cpp:2886`, `chronicletwo:ps2/src/editloop.cpp:993`), and leaving an interior reloads the outdoor roster only when the day or night window changed, or when the interior was entered with the outdoor villagers removed (`chronicletwo:ps2/src/editloop.cpp:2996-3003`). Nothing re-rolls the roster during a visit (inference from the callers).
- Party members are removed from the walk roster. `GetLoadVillagerList` adds 1000 to the villager number of any member whose party status is non-zero (`chronicletwo:ps2/src/scenevillager.cpp:530-535`). The table has only three such stand-ins, `NPC_INFO` 1012, 1015 and 1018 (models `p03_30a`, `p03_30a`, `p03_24a`), so the other joined members simply fail `GetVillagerModelName` and are skipped (`chronicletwo:ps2/src/vlgr_info.cpp:252-290`, `chronicletwo:ps2/src/scenevillager.cpp:697-720`). Inference: deliberate, to avoid a duplicate who walks with the party.
- Georama residents are party-candidate characters. A house takes one resident (`CEditHouse`/`npc_no[0]`, `chronicletwo:ps2/include/editdata.hpp:214`). The candidate list is party numbers 1 to 25 whose status is non-zero and not already in a house, with the 2 and 13 entries waiting for chapter 5 (`chronicletwo:ps2/src/editmenu.cpp:5187-5210`). The status bits are `IN_PARTY` 1, `JOINED` 2, `IN_HOUSE` 4 and `JOIN` 0x80 (`chronicletwo:ps2/include/userdata.hpp:124-129`).
- Each resident has its own admission rule in `CheckLiveChara`, keyed by character number. Examples: character 10 is refused in Benietio and, in any town, when a river is near; character 14 needs seven type-8 parts and a type-7 part in the territory, character 16 needs culture 20 or more (`chronicletwo:ps2/src/editanalyze.cpp:863-960`). Character 6 is refused unless flag 0x132 is set (`chronicletwo:ps2/src/editmenu.cpp:5504-5508`).
- Entering a house opens the removal menu `MENU_OPEN_REMOVAL` (`chronicletwo:ps2/src/editevent.cpp:337`). Confirming a move sets the party status to `IN_HOUSE` and writes `npc_no[0]` (`chronicletwo:ps2/src/editmenu.cpp:5533-5536`). A resident change returns `MENU_END_RESIDENT_CHANGE` (`chronicletwo:ps2/src/editmenu.cpp:5562-5565`).
- The door event adds an interior suffix from the resident's house type: `ia`, `ib`, `ic` or `id` for types 0 to 3, so a door to `a01` becomes `a01ia` and so on (`chronicletwo:ps2/src/editevent.cpp:201-214`, `chronicletwo:ps2/include/vlgr_info.hpp:31-37`). Interior maps are type 2 (`chronicletwo-data map/map0.cfg`, for example `a01ia` to `a05id`, with `a03` absent).
- Story scripts can make a resident walk the town. `GeoramaFunc` command 1 loads the scripted villager at the `npc_pos` function point (`chronicletwo:ps2/src/editevent.cpp:564-575`, `chronicletwo:ps2/src/editevent.cpp:613-676`). Command 2 (`LoadGeoNPC`) is active only in Stera (`chronicletwo:ps2/src/editevent.cpp:697`; the same test gates `GeoUpdateNpcPos` at `chronicletwo:ps2/src/editevent.cpp:780`), keyed on the Georama part `EDIT_GEO_NPC_PARTS_ID` 0x49 (`chronicletwo:ps2/include/editevent.hpp:25`).
- Script commands that move party state: `_SET_NPC_STATUS` (`chronicletwo:ps2/src/event_func.cpp:5664-5690`), `_JOIN_PARTY_MEMBER` (`chronicletwo:ps2/src/event_func.cpp:18469`), and `_CANCEL_LOAD_VILLAGER`, which suppresses both roster loads for the next load (`chronicletwo:ps2/src/event_func.cpp:18843-18847`).
- Player character in a town: `SetupMainUnit` builds the character from `active_chr_no` at entry (`chronicletwo:ps2/src/editloop.cpp:846-851`). A switch from the menu sets `ActiveCharaNo` and re-inits control (`chronicletwo:ps2/src/editloop.cpp:1320-1331`).
- Town resume through the title/menu load path (`next_loop == 2`): a saved main map of 10 resumes at the saved interior if that is 10 to 14, else at 10 (`chronicletwo:ps2/src/title.cpp:1057-1063`). `MapJump` also shifts the save's map fields, so `prev_map_no` gets the old map and `sub_map_no` is cleared (`chronicletwo:ps2/src/mapjump.cpp:191-225`) (unverified: the field names were not checked; the code writes the new map number and sets two entries to -1).
- The debug menus can build and export a layout. The Georama debug page writes the raw 0x5510-byte `CEditData` to `host0:geo_data/geo<map>-<slot>.edt` and reads it back (`chronicletwo:ps2/src/editdebug.cpp:398-406`). The "all Georama parts" script gives 30 of every part, opens every analysis request, and marks every geostone found (`chronicletwo:ps2/src/mainloop.cpp:1868-1913`).
- Port differences in this area: `CVillagerMngr::GetAppearVlgr` is replaced by a native-pointer version with the same algorithm (`chronicletwo:port/src/villagermngr.cpp:7-93`), because the retail code strides by `sizeof(void*)`, which is 4 bytes on PS2 (`chronicletwo:docs/PC.md:1138`). `CEditMap::GetePlaceIDList` is replaced (`chronicletwo:port/src/editmap.cpp:6-13`). Town camera and mouse control are replaced in `chronicletwo:port/src/editctrl.cpp:60-108`. Map load is replaced in `chronicletwo:port/src/sceneload.cpp:33`. Host builds drop `STATIC_ASSERT` (`chronicletwo:port/include/port.h:37`), so PS2 struct sizes are not enforced on PC.

### Files a Georama town loads

- `map/g/g0N/g0N.map`, `.mpk`, `.ipk`, `.efp`, `.sky` and `.cfg`: the scene files, with `.cfg` also read as the edit data (`chronicletwo:ps2/src/mapselect.cpp:306-325`, `chronicletwo:ps2/src/mapjump.cpp:251-300`).
- `map/g/g0N/g0N<lang>.gpi`: the part definitions for the language (`chronicletwo:ps2/src/editloop.cpp:2806-2811`).
- `map/g/g0N/g0N.stb`, with `g0N_<lang>.stb` overrides: the town script (`chronicletwo:ps2/src/mapjump.cpp:372-410`). Variant scripts `g0Nb.stb` and `g0Nc.stb` also sit in the folder; their use was not traced here.
- `map/cmn/g00/g00.*`: the add-on common set every Georama town except Moon Flower attaches (chronicletwo-data `map/map0.cfg` rows 0 to 3).
- `map/g/g00/g00.stb`: the script every Georama interior runs (`chronicletwo:ps2/src/mapjump.cpp:538-541`).
- `geo<lang>.cfg` at the data root: the analysis script shared by all five towns in that language (`chronicletwo:ps2/src/editdata.cpp:908-930`).
- `menu/<n>/wldmap.cfg`: the world-map places and areas, loaded by the world-map menu (`chronicletwo:ps2/src/menumap.cpp:484`).

### Arrival and map loading

`NextLoop(LOOP_EDIT, arg)` stores the next loop and an `INIT_LOOP_ARG` (`chronicletwo:ps2/src/mainloop.cpp:349`; struct at `chronicletwo:ps2/include/mainloop.hpp:213-221`). The main loop then calls `EditInit`, which sets up the camera stacks and the player character, then resolves the map by name and calls `EditMapJump` (`chronicletwo:ps2/src/editloop.cpp:800-877`). For `EditMapJump` the order is:

1. Clear the event and file caches. A map number of 11 to 14 is rewritten to 10, and the sub map is remembered (`chronicletwo:ps2/src/editloop.cpp:2731-2739`).
2. Save the layout of the map being left (`chronicletwo:ps2/src/editloop.cpp:2751`).
3. Build the load info from the map name, with the `f01_2` variant swap (`chronicletwo:ps2/src/editloop.cpp:2772-2779`).
4. `MapJump` clears the old map, loads the new one through the scene's staged loader (map info, models, effects and sky, parts table, function points, then the `.cfg`), and loads the script (`chronicletwo:ps2/src/mapjump.cpp:191-250`, steps at `chronicletwo:ps2/include/sceneload.hpp:37-43`).
5. For a Georama town, create the part table, read the `.gpi` and `.cfg` edit data, then `EditDataLoad` (`chronicletwo:ps2/src/editloop.cpp:2800-2829`).
6. Load the future-map layout, then the sound, the treasure box, the fire and geyser effects, the villagers and the sub map (`chronicletwo:ps2/src/editloop.cpp:2835-2895`).

The scene reads `<name>.cfg` into a buffer during the data stage (`chronicletwo:ps2/src/sceneload.cpp:60-80`) and parses it in the final stage, step six (`chronicletwo:ps2/src/sceneload.cpp:433-452`). `EditMapJump` reads the same file again for the edit data (`chronicletwo:ps2/src/editloop.cpp:2816-2817`). Inference: the scene path takes the scene tags and the edit path takes the Georama tags (`INIT_EPARTS`, `RIVER_PARTS_NAME`, `WATER_*`).

### Georama layout

`CEditData` is a pointer-free record: save count, culture points, up to 300 placed parts (0x24 bytes each), 32 houses, a placement log of 0x800 entries, a river grid of 0x400 bytes, and the analysis state (`chronicletwo:ps2/include/editdata.hpp:276-300`, constants at `chronicletwo:ps2/include/editdata.hpp:20-77`). A placed part records its definition id, state, angle, position as whole units on the edit grid, four colours, and its house. `CEditMap::SaveData` writes that from the live map (`chronicletwo:ps2/src/editdata.cpp:156`), and `LoadData` plus `InitialPlaceParts` rebuild it (`chronicletwo:ps2/src/editdata.cpp:318`, `chronicletwo:ps2/src/editmap.cpp:258`). A town with no save data yet starts from the `INIT_EPARTS` list (`chronicletwo:ps2/src/editmap.cpp:258`).

### Analysis and requests

`AnalyzeEditMap` dispatches on the town number to a per-town function (`chronicletwo:ps2/src/editanalyze.cpp:80-106`). Each function sets condition flags from the layout (`chronicletwo:ps2/src/editanalyze.cpp:241`, `chronicletwo:ps2/src/editanalyze.cpp:374`). A request is met when all its conditions hold, and each request has a percentage share of the town's future (`chronicletwo:ps2/include/editdata.hpp:107-120`, `chronicletwo:ps2/include/editdata.hpp:237-260`). The `geo_floor` field ties a request or condition to a dungeon floor, so a geostone from that floor reveals it (`chronicletwo:ps2/include/editdata.hpp:107-136`). The save keeps `data_open` and `condition_open` flags so the player only sees what is revealed (`chronicletwo:ps2/include/editdata.hpp:237-252`).

### Georama mode

Georama mode is entered from walking when the character stands on a valid spot (`chronicletwo:ps2/src/editloop.cpp:1775-1780`, `chronicletwo:ps2/src/editmode.cpp:796`). `EditMode` moves the cursor and applies the current tool each frame (`chronicletwo:ps2/src/editmode.cpp:1393`). Placement goes through `PlaceEditParts` and spends one copy of stock (`chronicletwo:ps2/src/editmode.cpp:1003`, `chronicletwo:ps2/src/editmode.cpp:1047`). Parts sit on a balance ground: `GroundBalance` weighs them and tilts the pieces (`chronicletwo:ps2/src/editmap2.cpp:745`). Houses are kept up to date by `UpdateHouse` (`chronicletwo:ps2/src/editmap2.cpp:684`). The culture points a layout earns are `CultureAnalyze`, stored as `culture_point` (`chronicletwo:ps2/src/editloop.cpp:3023-3047`).

### Villager roster

`LoadGameInfo` reads the place script into a `CVillagerPlaceInfo` table and the schedule script into a `CVillagerPlace` table with one slot per villager number up to 0x200 (`chronicletwo:ps2/src/vlgr_info.cpp:834-863`, `chronicletwo:ps2/include/villagermngr.hpp:85-187`, `chronicletwo:ps2/include/vlgr_info.hpp:22`). A place has a standing position, a talk offset, a map number, a motion, a walk speed, and a route of move and wait steps (`chronicletwo:ps2/include/villagermngr.hpp:85-143`). A schedule is a list of progress entries; each holds four alternatives with a noon place and a night place (`chronicletwo:ps2/src/vlgr_info.cpp:334-436`, `chronicletwo:ps2/include/villagermngr.hpp:156-170`). The `PROGRESS` second argument selects the alternative. A third, string argument whose Shift-JIS bytes spell an "onward from here" word marks the entry as applying to later progress too (`chronicletwo:ps2/src/vlgr_info.cpp:334-352`; the word is compared as bytes and is not reproduced here).

`GetAppearVlgr` returns every matching place for the requested map; the callers' arrays hold 32 (`chronicletwo:ps2/src/villagermngr.cpp:370-489`, `chronicletwo:ps2/src/scenevillager.cpp:681-690`). `LoadVillager` loads each model from `chara/<model>.chr`, copies a model already loaded for another villager where it can, registers the place, and sets the character active (`chronicletwo:ps2/src/scenevillager.cpp:681-760`, `chronicletwo:ps2/src/vlgr_info.cpp:287-300`). Main-map villagers use character slots 8 to 23, and sub-map villagers slots 24 to 31 (`chronicletwo:ps2/include/scenevillager.hpp:39-42`). `CVillagerMngr` holds 32 `CVillagerData` entries shared by both maps (`chronicletwo:ps2/include/villagermngr.hpp:246-252`). Each frame `Step` moves villagers along their route or through a camera pose (`chronicletwo:ps2/src/villagermngr.cpp:199`).

I ran a read-only simulation of the retail appearance rule against the extracted `place.cfg` and `npc_place4.cfg` (research script, not checked in). For progress points 1 to 10 and 100, both times of day, the largest count for any one map is 7 (Palm Brinks `m01` at progress 3, day), so the 16-slot and 32-entry limits hold for the shipped data (unverified: the script is not checked in and the counts were not re-run). Inference: adding villagers from elsewhere could break those limits without any check.

### Residents and houses

`CEditParts::GetLiveNPC` returns the first resident of a placed house (`chronicletwo:ps2/src/editparts.cpp:216-222`). `CEditMap::CheckLiveNPC` counts residents or tests for one (`chronicletwo:ps2/src/editmap2.cpp:419-445`). Residents move in and out through the removal menu (`chronicletwo:ps2/src/editmenu.cpp:5215`). `LeaveHouse` sets the party status to joined, and back to in-party if the character was in the party (`chronicletwo:ps2/src/userdata.cpp:3634-3648`). The house's own `npc_no` is cleared by the removal menu, not by `LeaveHouse` (`chronicletwo:ps2/src/editmenu.cpp:5418-5419`). `JoinPartyChara` sets the join status and copies the character's max point (`chronicletwo:ps2/src/userdata.cpp:3544-3556`).

## Ixion hooks

- **Town arrival from the Ixion layer:** call `EditMapJump(map_no)` (declared at `chronicletwo:ps2/include/editloop.hpp`, defined at `chronicletwo:ps2/src/editloop.cpp:2713`) after resolving the map by name with `SearchMapNo`. For a clean arrival, go through `NextLoop(LOOP_EDIT, INIT_LOOP_ARG)` so `EditInit` sets up the stacks; a direct call skips that setup.
- **World-map graph as the travel network:** the `POS` rows in `wldmap.cfg` are a graph of reachable places with flags and types (`chronicletwo:ps2/include/menumap.hpp:117-127`). An Ixion station or train place can be added as data (a `POS` row with a map number, a loop and a flag), without new code, provided the new map exists in the map table.
- **Georama and future twins:** the existing `f0N` maps already read `g0N`'s layout through slot `N-1` and `PartsOnOff` (`chronicletwo:ps2/src/editloop.cpp:2835-2851`). That is a working precedent for "same town, other time" and fits Dark Chronicle's time travel: the present and future versions of one town share a layout.
- **Layout as a portable blob:** `CEditData` is 0x5510 bytes with no pointers and a `PORT_RECORD_ASSERT` (`chronicletwo:ps2/include/editdata.hpp:446-447`), and the debug export already writes it as a file (`chronicletwo:ps2/src/editdebug.cpp:398-406`). Carrying a layout between worlds needs only the definition ids to exist on both sides.
- **Residents as cross-world cast:** a DC1 character can be placed into a DC2 house by party number, through `_JOIN_PARTY_MEMBER` or `_SET_NPC_STATUS` (`chronicletwo:ps2/src/event_func.cpp:18469`, `chronicletwo:ps2/src/event_func.cpp:5664`). Party numbers are 1 to 32, so the party table is the limit (`chronicletwo:ps2/src/userdata.cpp:3559-3566`).
- **Villager roster injection:** adding an `NPC` block with its `NPC_PLACE` rows in the two scripts, plus a model file and an `NPC_INFO` record, should make a new townsperson appear on any map the place names, with no code change (inference from the loaders). The roster is pure data plus progress and time, so an Ixion-only progress value could drive it (`chronicletwo:ps2/src/villagermngr.cpp:370-489`).
- **Time and the roster:** apart from entering an interior with the outdoor villagers removed, the day/night bucket is the only reload trigger found inside a town (`chronicletwo:ps2/src/editloop.cpp:2996-3003`). A cross-world time jump that changes the bucket would need an explicit `LoadVillager` call.
- **Dungeon-to-town unlock:** the `geo_floor` links in analysis requests are a data hook: an Ixion dungeon floor could reveal town requests through the same geostone path (`chronicletwo:ps2/include/editdata.hpp:107-136`).
- **Resume:** the title resume rule (`chronicletwo:ps2/src/title.cpp:1057-1063`) is the place to add an Ixion resume target.

## Risks and blockers

- **Positional map numbers.** The map number is the index in `map0.cfg`, and it is used as data in `place.cfg`, `wldmap.cfg`, the debug presets (`chronicletwo:ps2/src/mainloop.cpp:1309-1390`) and in hard-coded checks (`chronicletwo:ps2/src/editloop.cpp:883`, `chronicletwo:ps2/src/editloop.cpp:2736`, `chronicletwo:ps2/src/editanalyze.cpp:80-106`). Inserting a map record shifts every later number. Ixion needs an append-only or name-keyed table.
- **Five save slots.** `SAVE_EDIT_DATA_MAX` is 5 and the save struct is asserted at 0x65930 bytes (`chronicletwo:ps2/include/savedata.hpp:60`, `chronicletwo:ps2/include/savedata.hpp:504`). A sixth Georama town needs a save-format change and a version bump.
- **Save overflow exits the process.** `CEditMap::SaveData` calls `exit(0)` past 300 parts (`chronicletwo:ps2/src/editdata.cpp:156-300`). Any Ixion path that adds parts to a layout must check the count first.
- **Unchecked villager arrays.** `LoadVillager` writes into `chara_nos[32]` and `places[32]` and into character slots without a bound on `loaded` (`chronicletwo:ps2/src/scenevillager.cpp:681-760`). The shipped data peaks at 7 per map, but nothing enforces it.
- **Duplicate place record.** `NPC_PLACE 73` appears twice in `place.cfg` with different maps (26 and 82). Both blocks write the same slot, so the later block overwrites the map and position (`chronicletwo:ps2/src/vlgr_info.cpp:598-606`; data `place.cfg` lines 426 and 431). Inference: intended as the later one, but nothing warns.
- **Latent house-suffix index.** The door suffix is `suffix[info->house_type % 4]` (`chronicletwo:ps2/src/editevent.cpp:210`). A house type of -1 would index `suffix[-1]`. In the shipped data every candidate resident (party 1 to 25) has type 0 to 3, and the candidate list only admits those, so this is latent (inference from the candidate list).
- **Silent failures in the jump.** `EditMapJump` returns 0 when `GetLoadMapInfo` fails (the missing-name path is unverified: a name that `SearchMapNo` cannot find gives -1, which was not traced to the same return), and no caller checks it (`chronicletwo:ps2/src/editloop.cpp:2772`, `chronicletwo:ps2/src/editloop.cpp:877`). `GetMapName` falls back to a shared static buffer for an unknown number (`chronicletwo:ps2/src/mapselect.cpp:367-379`), so `SearchMapNo` can return -1 without an error. A failure after `EditDataSave` leaves the scene half set up.
- **Port override parity.** The retail `GetePlaceIDList` tests byte 0x70 of each slot to find a free part. The port test is `name[0] != 0` (`chronicletwo:port/src/editmap.cpp:6-13`, retail at `chronicletwo:ps2/src/editmap.cpp:461-480`). These match only if `CEditParts::name` lies at that offset on PS2, which this research did not confirm.
- **Party remap drops members.** Only three of the joined townspeople have stand-ins. The others silently disappear from the walk (`chronicletwo:ps2/src/scenevillager.cpp:530-535`).
- **Heim's fire is a one-way burn.** Every route that calls `BurnEditParts` first (world move, event jump, debug jump, leaving the loop) burns Heim's parts, refunds stock and evicts residents, and the flag is the only guard (`chronicletwo:ps2/src/editloop.cpp:1378`, `chronicletwo:ps2/src/editloop.cpp:1554`, `chronicletwo:ps2/src/editloop.cpp:1406`, `chronicletwo:ps2/src/editloop.cpp:517`). A bare `EditMapJump` does not burn, so an Ixion exit from Heim must either call the same burn or skip the save.
- **Build stock is shared.** `build_parts_num` is global across towns, so a part refunded from one town is spendable in another (`chronicletwo:ps2/src/savedata.cpp:111-145`).
