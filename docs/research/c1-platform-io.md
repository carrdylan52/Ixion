# Chronicle platform I/O: input, audio, config, paths and process state

## What this covers

The host-facing half of the Chronicle (DC1) PC port: process start-up and command-line handling, the environment variables it reads, `config.json`, the save and data roots, the save-slot layout, the pad, keyboard, mouse and touchpad path, the audio output and mixer, the soundtrack override, Discord presence, and the first-run flow. It also lists which of these are process-wide singletons, which would collide if a second game (ChronicleTwo, "DC2") ran in the same process, and which paths and config files need per-game namespacing.

Most of the host layer is not in the Chronicle tree. It is Kazarov's `port/platform`, `port/audio` and `port/sce` (Chronicle pins Kazarov at a0a5ff8, see `kz_port_host_library(dc_host)` in chronicle:port/CMakeLists.txt). Chronicle's own platform code is `port/src/platform/{config,discord,firstrun,save_state}.cpp`, `port/src/save_slots.cpp`, `port/src/presence.cpp`, `port/src/identity.cpp` and the game-side glue in `port/src/{main,gamepad,dualsense,sound,memorycardaccess,runtime,gameloop}.cpp`.

Line numbers: `chronicle:` is the Chronicle checkout at master 3bc16763; `kazarov:` is a0a5ff8 unless marked `@9310c53` (Kazarov main); `chronicletwo:` is the ixion branch of the ChronicleTwo checkout, whose Kazarov pin is 3dc38ce.

## Key facts

- **Entry order.** `Run()` calls `GameSetIdentity()` first, then `PathsConsumeArgs()`, then its own option parser, then `FirstRunIfNoData`, `RequireData`, `ConfigLoad()`, `SoundtrackEnsure()`, `WindowInit`, `InputInit`, the renderer, `AudioOutputStart`, the clock pump hook and `RunGame` (chronicle:port/src/main.cpp:367-455). Config is therefore read before any window or audio exists.
- **Identity is process-global.** `GameSetIdentity()` sets the env prefix `DC`, `PathsConfigure({app_dir "chronicle", env_data DC_DATA, env_save DC_SAVE})`, and the window title "Dark Cloud" with app id `dcdecomp.darkcloud` (chronicle:port/src/identity.cpp:8-15). Kazarov stores the prefix in a file-static string (kazarov:port/platform/settings.cpp:8,14-19).
- **Two ways to read env vars.** Most Chronicle env reads go through `SettingsEnv`, so they are `DC_<name>`. Several bypass the prefix and call `std::getenv("DC_...")` directly: `DC_BGM_TEST` (chronicle:port/src/main.cpp:202), `DC_INPUT` (main.cpp:246-251), `DC_PRESENT_STATS` (main.cpp:331), `DC_JUMP` and `DC_GIVE` (main.cpp:374-377), `DC_FAST_LOAD` (main.cpp:387), `DC_SPRITE_TRACE` (chronicle:port/src/snd.cpp:63, gameutil_sprite.cpp:45), `DC_TEXTURE_DUMP` (chronicle:port/src/texture.cpp:109), `DC_LOCALIZE_TRACE` (chronicle:port/src/localize.cpp:156). Changing the prefix per game would not move these.
- **The full env surface.** Prefix-routed: `DC_DATA`, `DC_SAVE`, `DC_AUDIO` (only `off` is read), `DC_AUDIO_WAV`, `DC_AUDIO_TRACE`, `DC_VULKAN_VALIDATION` (`SettingsEnv("VULKAN_VALIDATION")`, chronicle:port/src/main.cpp:431, firstrun.cpp:486), and the Kazarov `AUDIO_*` names (kazarov:port/platform/audio.cpp:139-142, kazarov:port/audio/trace.cpp:12). Non-prefixed: `FLATPAK_ID` (chronicle:port/src/platform/firstrun.cpp:350), and for Discord the IPC search dirs `XDG_RUNTIME_DIR`, `TMPDIR`, `TMP`, `TEMP` (chronicle:port/src/platform/discord.cpp:143-150).
- **Command line.** `--data` and `--save` (with `=` or a separate value) are removed from argv by Kazarov's `PathsConsumeArgs` before Chronicle's parser runs (kazarov:port/platform/paths.cpp:135-172). Everything else is Chronicle's: `--headless`, `--offscreen`, `--frames`, `--screenshot`, `--screenshot-fps`, `--input`, `--width`, `--height`, `--jump`, `--give`, `--fast-load`, `--export-text`, `--font`, `--show-fps`, `--display-per-tick` (chronicle:port/src/main.cpp:71-96 for `Usage`). Windows builds convert wide argv in `wmain` (chronicle:port/src/main.cpp:650-660). Unknown flags print usage and exit with `kExitUsage`.
- **The mixer is one object.** `audio::DefaultMixer()` is a function-local `static Mixer *` (kazarov:port/audio/mixer.cpp:673-676, `Mixer` 16 ports x 16 banks, 48-voice synth, mixer.hpp:27-40). Chronicle's sound manager routes every call through `Player()`, which returns it (chronicle:port/src/sound.cpp:73-79). The port index is the PS2 `MIDI_PORT_*` enum, e.g. BGM = 0, `MIDI_PORT_UNK_A` = 10, `MIDI_PORT_SE_TITLE` = 15 (chronicle:ps2/include/sound.hpp:10-18).
- **Audio output starts once per process.** `AudioOutputStart` returns `true` immediately if a stream already runs, ignoring the new render callback (kazarov:port/platform/audio.cpp:130-133). Chronicle calls it twice: from `main` with `RenderAudio` (chronicle:port/src/main.cpp:437, 266-268) and from `CSound::Init`, guarded by a function-local `static bool output_started` (chronicle:port/src/sound.cpp:496-503). Both pass the same `DefaultMixer`.
- **Clock is one object with single-slot hooks.** `g_clock` is file-static in Kazarov (kazarov:port/platform/clock.cpp:32). `ClockSetTickCallback` and `ClockSetIdleHook` each hold one function pointer (clock.cpp:107, 115); `ClockAddPumpHook` is a list (clock.cpp:123). Chronicle's `MGInit` sets the tick callback to null and calls `ClockReset()` (chronicle:port/src/mglib.cpp:539-540); `MGInitVSyncCallBack` installs the game's callback (mglib.cpp:544-545); the loading screen sets its own idle callback (chronicle:port/src/nowload.cpp:251).
- **SDL is process-wide and shut down wholesale.** `WindowInit` calls `SDL_SetAppMetadata` (kazarov:port/platform/window.cpp:62) and sets video and audio driver hints (window.cpp:66-70), then `SDL_Init(VIDEO)` (window.cpp:72). `WindowShutdown` calls `SDL_Quit()` (window.cpp:161-166), which tears down every subsystem, including gamepad and audio. `InputShutdown` and `AudioOutputStop` also call `SDL_QuitSubSystem` (kazarov:port/platform/input.cpp:756; audio.cpp:189).
- **Libc is overridden for the whole binary.** Chronicle defines `srand`, `rand` (a private LCG), `exit__2`, and `mwInit` at link level (chronicle:port/src/runtime.cpp:30-47). The `rand` override is load-bearing: the comment says a fire reseeds the generator each tick and the title's lightning depends on the exact sequence (runtime.cpp:19-24). `exit__2` calls `std::exit`, so one game's exit ends the process.
- **Config is one global struct.** `Config g_config` is file-static (chronicle:port/src/platform/config.cpp:22); `ConfigGet()` returns it (config.cpp:564-566). `Config` is `HostSettings` plus Chronicle fields (chronicle:port/src/platform/config.hpp:36-70). `SettingsGet()`/`SettingsChange()` are the bridge Kazarov calls (config.cpp:568-576). Kazarov's `HostSettings` carries the shared settings: tick rate 60 Hz, present mode, window size, fullscreen, FPS overlay, volume, surround, soundtrack, key bindings, mouse, gyro, touchpad, lightbar, rumble, glyphs (kazarov:port/platform/settings.hpp:49-90).
- **config.json is rewritten whole.** `ConfigSerialize` builds a fresh JSON object from fields (config.cpp:614-620), so keys or sections not in Chronicle's schema are dropped on the next save. `ConfigSave` writes `config.json.tmp` and renames it (config.cpp:541-557, 684-690). `ConfigLoad` writes a default file if none exists and warns about a legacy `config.ini` (config.cpp:693-705). Sections are `game`, `video`, `audio`, `input`, `discord` (config.cpp:614-660; config.hpp:15-17 comment).
- **Settings changes fan out through a list.** `ConfigChange` saves, then runs every registered hook in order with `(before, after)` (config.cpp:727-750). Chronicle registers four: `ApplyConfigChange`, `ConfigDisplayChanged`, `GameOptionsChanged`, `LocalizeConfigChanged` (chronicle:port/src/main.cpp:445-448). `ConfigAppliesOnRestart` lists only `game.debug_mode` (config.cpp:752-754).
- **Input layer is Kazarov's.** Two DualShock-2-shaped pads, keyboard and mouse fold into `InputPadState` (kazarov:port/platform/input.hpp:40-58). Global state is file-static: `g_slots` (SDL gamepad handles and rumble), `g_device`, `g_state`, `g_view`, `g_override`, `g_keys`, `g_mouse_look`, `g_latch_serial`, `g_stick_live`, `g_gamepad_subsystem`, `g_touchpad`, `g_lightbar_on` (kazarov:port/platform/input.cpp:168-212). `InputInit` opens the gamepad subsystem, applies config bindings, and registers `InputHandleEvent` on the window hook list (input.cpp:668-678).
- **Game-side pad read.** Chronicle overrides `pad_button_read`. For port 0 it calls `InputLatchPad`, then `DualSenseUpdate()`, then `MenuMouseUpdate()`, then reads `InputHostPressed(DebugMenu)`, and finally `scePadRead` (chronicle:port/src/gamepad.cpp:25-50). `CGamePad::GetLX/GetLY` call `InputNoteLeftStickRead` (gamepad.cpp:49-58). `scePadRead` is the libpad shim that copies `InputGetPad(port)` (kazarov:port/sce/libpad.cpp:43-58).
- **Mouse is one relative-mode window.** Mouse capture is `SDL_SetWindowRelativeMouseMode` on the single window handle (kazarov:port/platform/mouse.cpp:25). Mouse-look deltas are consumed on each read of pad 0 (`InputLatchPad`, input.cpp:876); motion older than 0.25 s is dropped (input.cpp:140, `kMouseLookMaxGapSeconds`).
- **Menu pointer state is file-static.** `MenuMouseUpdate` (chronicle:port/src/menu_mouse.cpp:994-1032) drives per-screen `MenuPointer`s `g_save`, `g_battle` and the discard/scroll state (menu_mouse.cpp:42-46, 133, 197-201). `MenuPointer`'s `synthetic` and `shown` are file-static (chronicle:port/src/menu_pointer.cpp:24-25).
- **DualSense lightbar.** `DualSenseUpdate` reads the game globals `mode` and `UserStatus` and pushes pad 0's colour to `InputSetLightbar` every tick (chronicle:port/src/dualsense.cpp:25-34). Only pad 0 is coloured.
- **Save root contents.** `PathsSaveRoot()` holds: `config.json` (config.cpp:684-700), `saves/<N>/save.dat` and `saves/state.json` (chronicle:port/src/save_slots.cpp:22-35), `pipeline_cache.bin` (chronicle:port/src/main.cpp:427), `lang/` for `textwipe_tuning.json` (chronicle:port/src/textwipe.cpp:135-137) and as a second language directory (chronicle:port/src/localize.cpp:67-79), `lang-export/` seeded on first run (main.cpp:395-402), and `host0/` for debug `WriteFile` output (chronicle:port/src/dataread.cpp:290-306).
- **Data root contents.** `InitCDFile()` indexes every regular file under `PathsDataRoot()` recursively into a process-global `data_index` map (chronicle:port/src/dataread.cpp:118-135, 26-27). The `normalized/` subfolder is read as well (dataread.cpp:136-140). Nothing is keyed by game.
- **Soundtrack override.** `SoundtrackEnsure()` creates `soundtrack/soundtrack.json` beside the save root's parent (kazarov:port/audio/soundtrack.cpp:83-103), and the reader uses the same parent (soundtrack.cpp:40). The mapping lives in a file-static map (soundtrack.cpp:32-35). Chronicle calls `SoundtrackEnsure` from `Run` (main.cpp:411).
- **Save slots are a fixed layout.** `SaveSlotsRoot()` is `<save>/saves` (save_slots.cpp:22-24); `SaveStatePath()` is `saves/state.json` (save_slots.cpp:34-36). `SaveSlotFiles()` lists every numeric subfolder name, readable or not (save_slots.cpp:53-65), so an unreadable folder still takes its number. A listed save must carry the version string `darkcloudVer1.9`, which the PS2 source sets (chronicle:ps2/src/memorycardaccess.cpp:58) and the port compares (chronicle:port/src/memorycardaccess.cpp:56-58, listed at 183-186).
- **Deletion has no owner check.** `CMemoryCardAccess::DeleteFile` removes `save.dat` and then the numbered folder for whatever number it is given (chronicle:port/src/memorycardaccess.cpp:300-309). It does not check which game wrote the folder.
- **Atomic writes.** Saves and state go through Kazarov's `FilesWrite`/`FilesCreateDirectory`, a temp-file-then-rename write (kazarov:port/platform/files.hpp:1-26; chronicle:port/src/memorycardaccess.cpp:261; platform/save_state.cpp:50-56).
- **Discord is one client and one thread.** The client id is a constant (chronicle:port/src/platform/discord.hpp:14). `DiscordStart` is a no-op if its thread already runs (discord.cpp:388-392). The thread is file-static in `g_state` (discord.cpp:57-67). `ApplyDiscord` runs only when `discord.rich_presence` is on and the run is not headless (chronicle:port/src/main.cpp:302-307; `discord_rich_presence = true` by default, config.hpp:50). Presence reads DC1 state: `BtGameModeFlag`, `SaveData` (chronicle:port/src/presence.cpp:134-140).
- **First run.** `FirstRunIfNoData` runs before config load. With empty or missing data it opens a file chooser, extracts into `<root>.partial`, and renames when every file checks out (chronicle:port/src/platform/firstrun.hpp:1-42; firstrun.cpp:452).
- **Game save state is a static.** `g_save_data` is a file-static `CSaveData` in the port (chronicle:port/src/gameloop.cpp:215-217), set as `SaveData` in `RunGame` (gameloop.cpp:791-830).
- **Test env.** Tests set `DC_DATA`/`DC_SAVE` with `SetEnv` (chronicle:port/src/tests/data_read_test.cpp:269-280), which is process-wide and would need the same care in a combined test binary.
- **snd.cpp is not audio.** Chronicle's `snd.cpp` holds the sprite and 2D draw overrides (`set2DSprite`, `set3DSprite`, `setColSprite`, `SndSetReadBuffer`) and a global `g_linear` bilinear flag (chronicle:port/src/snd.cpp:11-20, 63-70, 140-146). Audio is `sound.cpp`.
- **ChronicleTwo's pins differ.** DC2 sets `SettingsSetEnvPrefix("DC2")`, `app_dir "chronicletwo"`, `DC2_DATA`/`DC2_SAVE`, and two flags that exist only in newer Kazarov: `installed_save_default` and `coherent_default_root` (chronicletwo:port/src/identity.cpp:7-11; kazarov@9310c53:include/platform/paths.hpp:24-30). Chronicle's a0a5ff8 `PathsConfig` has only the three string fields (kazarov:port/platform/paths.hpp:24-28). So the two games resolve default roots differently.
- **Symbol collisions already present in ChronicleTwo.** Both trees define `struct Config`, `enum class ConfigAspect`, `ConfigGet`, `ConfigLoad`, `ConfigChange`, `ConfigParse`, `ConfigSerialize`, `SettingsGet`, `SettingsChange`, `srand`, `rand`, `mwInit`, `exit__2`, `main`/`wmain` (chronicle:port/src/platform/config.hpp:10-124; chronicletwo:port/src/platform/config.hpp:13-47; chronicletwo:port/src/platform/config.cpp:541-556; chronicletwo:port/src/runtime.cpp:30-34). The change-hook type differs: Chronicle's takes `const Config &` (config.hpp:103) and DC2's takes `const HostSettings &` (chronicletwo:port/src/platform/config.hpp:40), and DC2 registers a single slot (`ConfigSetChangeHook`, chronicletwo:port/src/platform/config.hpp:41).
- **Both games use the same mixer and save names.** DC2 calls `audio::DefaultMixer()` in `audio_init.cpp:33,92` and `sound.cpp:130,176,203`, where `CSound::Init` calls `DefaultMixer().Reset()` (chronicletwo:port/src/sound.cpp:196-204). DC2 uses `saves/` (chronicletwo:port/src/save_slots.cpp:288), `mc0`/`mc1` folders (save_slots.cpp:398), `key_cap.bin` (chronicletwo:port/src/gamepad.cpp:157, 176), `pipeline_cache.bin` (chronicletwo:port/src/main.cpp:289) and `config.json` (chronicletwo:port/src/platform/config.cpp:457, 513). These are the same names Chronicle uses.
- **No Discord in the ixion checkout.** A search of the ChronicleTwo `port/src` finds no Discord module on this branch.
- **Docs drift.** `docs/PC.md` describes `DC_AUDIO_TEST_WAV` and `audio_real_title_*` tests (chronicle:docs/PC.md:1105-1106); neither appears in the Chronicle tree or Kazarov at a0a5ff8. The same section says the WAV capture writes "N/50 s" (PC.md:1102-1103), but the default tick rate is 60 Hz (kazarov:port/platform/settings.hpp:50), and PC.md's own clock section says 60 Hz (PC.md:881).

## How it works

**Start-up.** `Run` names the process, consumes `--data`/`--save`, parses options, and handles the first-run and missing-data cases. It then loads config from `PathsSaveRoot()/config.json`, starts the soundtrack mapping, and opens the window and input. The renderer gets `PathsSaveRoot()/pipeline_cache.bin` (main.cpp:427). Audio starts on the mixer's rate with `RenderAudio` (main.cpp:437). The clock is given `PumpHost` (main.cpp:441), which pumps window events, runs the first-run check, re-applies frame layout, samples input and runs `InputScriptApply` (main.cpp:221-235). `RunGame` then calls `InitCDFile`, `GamePad.Init`, `MGInit`, and sets `SaveData` to the static (gameloop.cpp:800-830).

**Paths.** Kazarov resolves each root once and caches it. For data: `--data`, then `DC_DATA`, then `./data`, then `data/` beside the executable, then the per-user install directory (`%LOCALAPPDATA%\chronicle` on Windows, `$XDG_DATA_HOME/chronicle` or `~/.local/share/chronicle` otherwise) (kazarov:port/platform/paths.cpp:34-80, 188-192). For saves: `--save`, then `DC_SAVE`, then `./save`, then `save/` beside the executable or beside a local `data/`, and only then the install directory (paths.cpp:198-223). Saves are created on first use. The data-root reference is cached in `data_root` and the save root in `save_root` (paths.cpp:25-28, 186-223). `PathsSetSaveRoot` resets the optional that every earlier `const fs::path&` points into (paths.cpp:183-186), so a reference held across a change sees the new value or is dangling; treat it as invalid.

**Config.** `ConfigLoad` parses JSON with comments and `ConfigParse` applies each key over defaults, reporting unknown keys and bad values to stderr (config.cpp:588-615). The settings screen calls `ConfigChange`, which re-parses the serialized form (so the stored value is what a file read would give), saves, and runs the hooks (config.cpp:727-750). Changes to `video.width`/`height`/`fullscreen` go through `DisplayChanged` (`ConfigDisplayChanged`, chronicle:port/src/platform/config.cpp:723).

**Input.** Pads, keyboard and mouse are sampled once per tick in `InputPoll`, folded into `g_device`, then `g_state` (view for the game). Each game read of pad 0 calls `InputLatchPad`, which closes one mouse-look interval and advances `g_latch_serial`. `InputGetPad` returns the state the game reads. Host actions (`fps_toggle`, `developer_menu`, `debug_menu`, `gyro_hold`, `zoom_reset`) are polled separately (kazarov:port/platform/input.cpp:618-660). Bindings come from `input.bindings`: `EnsureBindings` sets the defaults (input.cpp:302-313), and `InputApplyConfig` resets them and rebinds from config (input.cpp:680-691).

**Audio.** The mixer renders in `RenderAudio`/`RenderOutput` on SDL's audio thread (kazarov:port/platform/audio.cpp:71-88). Each MIDI port (16 of them) owns a bank and a sequence, and `CSound` maps the game's sound slots onto ports. A `SoundtrackFor` lookup can swap a sequence for a user recording (sound.cpp:301; soundtrack.cpp:108-127). Master gain and surround are applied from config on start and on each change (main.cpp:311-314, 435-436). Stereo follows `options.stereo` (sound.cpp:643-646).

**Saves.** A numbered folder is a save. Writes replace `save.dat` atomically. Reads validate the version string and per-64-byte checksums before listing (memorycardaccess.cpp:55-80). `state.json` carries `last_save` and `game_clear` (platform/save_state.cpp).

## Ixion hooks

Each hook is a place where Ixion could take ownership or give each game its own copy. The ordering matters: several calls already overwrite each other.

- **One host, two games.** Ixion's entry point should own `GameSetIdentity`-equivalent setup once, before either game's `PathsConfigure`/`SettingsSetEnvPrefix`. Those calls are process-wide and last-write-wins (chronicle:port/src/identity.cpp:8-14; chronicletwo:port/src/identity.cpp:7-12).
- **Window and SDL.** Keep one `WindowInit`/`InputInit`/`AudioOutputStart`. Stop each game's `WindowShutdown`/`InputShutdown`/`AudioOutputStop` from running on game exit, because each calls `SDL_Quit` or `SDL_QuitSubSystem` process-wide (kazarov:port/platform/window.cpp:161-166; input.cpp:731-757; audio.cpp:179-190).
- **Audio.** The natural seam is `Player()` (chronicle:port/src/sound.cpp:73-75) and DC2's `audio::DefaultMixer()` call sites (chronicletwo:port/src/audio_init.cpp:33,92; sound.cpp:130). Give each game its own `audio::Mixer` instance, and have one render callback sum the two (kazarov:port/platform/audio.cpp:130-155 currently takes one callback). Change `CSound::Init`'s `DefaultMixer().Reset()` (chronicletwo:port/src/sound.cpp:203) so it touches only that game's mixer.
- **Clock.** Give each game a clock instance or wrap the single one. The hooks are `ClockSetTickCallback`/`ClockSetIdleHook` (kazarov:port/platform/clock.cpp:107-115), Chronicle's `MGInit` reset at mglib.cpp:539-540, and `MGInitVSyncCallBack` at mglib.cpp:544-545. Only one game should drive the clock at a time, with the other paused. Ixion's switch function would call `ClockSetTickCallback` for the active game.
- **Pad read.** Only the active game should call `InputLatchPad` and `InputNoteLeftStickRead` (chronicle:port/src/gamepad.cpp:25-62). Otherwise the mouse-look delta is consumed by whichever game reads first. `DualSenseUpdate` (dualsense.cpp:25-34) should be routed through the active game's party data.
- **Config.** Split into a host file (video, audio, input, discord) and per-game sections, or one file per game under each game's save root. Chronicle's serializer drops unknown sections (config.cpp:614-620), so a shared file needs a merge step in Ixion. `ConfigChangeHook` types differ between the two games (chronicle:port/src/platform/config.hpp:103; chronicletwo:port/src/platform/config.hpp:40), so one hook registration point is needed.
- **Paths.** Ixion should resolve `DC_DATA`/`DC2_DATA` and per-game save roots itself, then pass them in. Kazarov has only one data root and one save root per process (kazarov:port/platform/paths.cpp:25-28). The practical layout is `<ixion-save>/chronicle/` and `<ixion-save>/chronicletwo/`, each holding its own `config.json`, `saves/`, `state.json`, `lang/`, `soundtrack/`, `pipeline_cache.bin`, `host0/`, `key_cap.bin`. The shared `pipeline_cache.bin` should be split first, because two shader sets would overwrite it (chronicle:port/src/main.cpp:427; chronicletwo:port/src/main.cpp:289).
- **Data indexing.** `InitCDFile` indexes the whole data root (chronicle:port/src/dataread.cpp:118-135). Pointing both games at one data root would index both sets together. Each game needs its own `data_index`.
- **Env.** Keep one prefix per game (`DC_` and `DC2_`) through `SettingsEnv`. Convert the direct `std::getenv("DC_...")` reads to `SettingsEnv` or to a per-game lookup, or document which names are global (list in Key facts).
- **Command line.** Ixion's parser should consume `--data`/`--save` for each game, but `PathsConsumeArgs` only accepts one pair (kazarov:port/platform/paths.cpp:135-172). Option: `--dc1-data`, `--dc1-save`, `--dc2-data`, `--dc2-save`, handled by Ixion before calling either game's parser.
- **Discord.** Keep one presence owner. `DiscordStart` is a no-op once a thread runs (chronicle:port/src/platform/discord.cpp:388-392), so the first caller wins. Ixion should decide whether it presents its own activity, or forwards the active game's `PresenceDescribe` (chronicle:port/src/presence.cpp:79-149) through one client id.
- **libc overrides.** `rand`, `srand`, `exit__2`, `mwInit` (chronicle:port/src/runtime.cpp:30-47) are defined for the whole binary. Two games cannot each define them. Rename each game's to a per-game symbol through the stubs layer (`port/include/stubs`) and call through a per-game RNG, so each game keeps its own sequence.
- **Save slots.** Namespace `SaveSlotsRoot` by game (chronicle:port/src/save_slots.cpp:22-24). `SaveSlotFiles` already counts unreadable numeric folders as taken (save_slots.cpp:53-65), so a shared `saves/` would make each game's numbering skip the other's saves. `DeleteFile` (memorycardaccess.cpp:300-309) has no owner check, so a shared folder lets one game delete the other's save.
- **Soundtrack.** `soundtrack/` is beside the save root's parent (kazarov:port/audio/soundtrack.cpp:40, 83). Two games sharing a parent share one mapping. Namespace it per game.
- **First run.** `FirstRunIfNoData` handles one data root (chronicle:port/src/platform/firstrun.cpp:452-470). Ixion needs a per-game first run or one combined extraction step.
- **Text and localisation.** `lang/` is read from the executable folder and the save root (localize.cpp:67-79), and `font.ttf`/`font_thin.ttf` are looked up by name (localize.cpp:670-690). Both games would read the same `lang/` folder unless Ixion namespaces the lookup. `LanguageCode` is game-global (gameloop.cpp:844-853).

## Risks and blockers

- **Shared SDL shutdown.** `WindowShutdown`, `InputShutdown` and `AudioOutputStop` all end SDL subsystems process-wide (kazarov:port/platform/window.cpp:166; input.cpp:756; audio.cpp:189). One game's exit or restart would silence the other.
- **Symbol collisions at link time.** `Config`, `ConfigGet`, `ConfigLoad`, `ConfigChange`, `SettingsGet`, `SettingsChange`, `main`, `rand`, `srand`, `exit__2`, `mwInit` appear in both trees with matching or near-matching signatures (see Key facts). Linking both games into one binary fails or silently picks one. A single binary needs per-game namespaces (C++ `namespace` or symbol renaming), or separate shared libraries loaded with `dlopen`/`LoadLibrary`.
- **Pinned Kazarov versions disagree.** Chronicle is at a0a5ff8, ChronicleTwo at 3dc38ce, and Kazarov main is 9310c53. The `PathsConfig` and `WindowIdentity` shapes differ between pins (kazarov:port/platform/paths.hpp:24-28 vs kazarov@9310c53:include/platform/paths.hpp:24-30). Ixion must pick one pin and port both games to it.
- **Mixer reset.** DC2's `CSound::Init` calls `DefaultMixer().Reset()` (chronicletwo:port/src/sound.cpp:203). If DC1 is playing from the same mixer, its voices go silent when DC2 initialises.
- **Clock reset.** Chronicle's `MGInit` calls `ClockSetTickCallback(nullptr)` and `ClockReset()` (mglib.cpp:539-540). Starting a second game's `MGInit` resets the first game's clock anchor and drops its tick callback.
- **Float rounding and tick timing.** Kazarov's clock and mixer advance on wall time or tick count. Two games sharing the clock would change each other's tick cadence, which the game's timing assumes (clock.hpp header comment).
- **rand is load-bearing.** The DC1 `rand` override is what makes fire and title effects match (runtime.cpp:19-24, 35-40). Replacing it for DC2 (or giving DC2 its own global) changes DC1's sequence if both run in one process.
- **Save deletion across games.** `DeleteFile` removes whatever is at the numbered path (memorycardaccess.cpp:300-309).
- **config.json loss.** A save from one game drops the other game's keys (config.cpp:614-620, 684-690). This needs a merge step or separate files.
- **Discord policy.** Rich presence is on by default (config.hpp:50). It speaks to the local Discord IPC pipe (discord.cpp:143-150), and the Discord client reaches Discord's service. Whether that fits the project's LAN-only rule is the project owner's call, not this document's.
- **Docs drift.** `DC_AUDIO_TEST_WAV` and `audio_real_title_*` are documented but absent (PC.md:1105-1106). The "N/50 s" audio duration contradicts the 60 Hz default (PC.md:1102-1103; settings.hpp:50). Do not rely on these lines without checking.
- **Reference lifetime.** `PathsSetSaveRoot`/`PathsSetDataRoot` reset the cached optionals (paths.cpp:178-186), and the next `PathsSaveRoot()` call refills them. A `const fs::path&` held across a change either sees the new value or dangles. Ixion must not switch roots while a game holds one.

## Open questions

- Single process (shared window, audio, input, clock) or separate processes with handoff? Almost every hook above depends on this. A separate-process design removes the SDL, clock, mixer and libc collisions but adds IPC for the pad and save transfer.
- Which Kazarov pin does Ixion adopt? Chronicle's a0a5ff8 lacks the `coherent_default_root` and `installed_save_default` flags that DC2 uses (kazarov@9310c53:include/platform/paths.hpp:28-29).
- Should Ixion's config be one file (host sections shared, game sections per game) or one file per game? Which keys are host-owned: video, audio and input seem host-wide, while `game.*` looks per game (config.hpp:15-17 comment).
- Do the two games share one `pipeline_cache.bin`? If the shader sets differ, it should be per game (chronicle:port/src/main.cpp:427).
- Who owns Discord presence, and does the Discord client's external connection satisfy the LAN floor (see Risks)?
- Do the `DC_JUMP`/`DC_GIVE` test hooks need to remain callable per game, given they are read by raw `getenv` (main.cpp:374-377)?
- Is `GameOptionsApply` (gameloop.cpp:295, 901) per game? Options are saved into each save (`config.hpp:15-17`), so one game's stereo setting would leak into the other's saves unless the copy is per game.
