# ChronicleTwo save format

## What this covers

How ChronicleTwo (Dark Chronicle, PAL, DC2) writes and reads its saves, on the retail PS2 path and on the PC port: the save image (`SAVEDATA_FORMAT`), the game-state record it carries (`CSaveData` and its nested layouts), the check digits, the PC flat-file catalog and its legacy card import, the separate bonus (omake) file, and the flags and fields Ixion would read or write. Offsets for `CSaveData` and `CUserDataManager` were computed from the struct declarations (member sizes and alignments) and cross-checked against the offset names the source gives to unknown fields (`unk_1D298`, `unk_643EC`, `unk_44d95`). Nothing was built or run. Inference is labelled.

## Key facts

- The save image is `SAVEDATA_FORMAT`, 0x659C0 bytes on PS2: an 0x80-byte header, then `CSaveData` (0x65930 bytes) at +0x80, then 0x10 unused bytes. chronicletwo:ps2/include/memcard.hpp:232-258 (`STATIC_ASSERT` at line 258).
- Header fields (PS2 offsets): `version` +0x00 (16 bytes), `costume_bit` +0x10, `debug_code` +0x18, `check_digit_half` +0x28, `check_digit` +0x2C, `map_no` +0x30, `program_loop_no` +0x34, `dungeon_no` +0x38, `floor_id` +0x3C, `progress` +0x40, `dng_tree_flag` +0x44, `incomplete` +0x45, `omake_flag` +0x46, `fish_num` +0x48, `unique_counter` +0x78. chronicletwo:ps2/include/memcard.hpp:232-256; cross-checked with refs/ChronicleTwo/ps2/re/docs/memcard/notes.md:89-101.
- The current version string is `"dc2Ver4"`; the only older accepted version is `"dc2Ver2"`. Ver2 is the older layout: its digits are not checked and its inventions are converted on load. chronicletwo:ps2/src/memcard.cpp:222 (set in `Initialize`); chronicletwo:ps2/src/memcard.cpp:1302-1304 (load check); chronicletwo:port/src/save_slots.cpp:362-363.
- Retail file and directory names: directory `/BESCES-51190dkcl<N>` with file `BESCES-51190dkcl<N>` inside it; album `/BESCES-51190dc2album` (built twice, so the name is repeated); bonus `/BESCES-51190dc2omake/BESCES-51190dc2omake`. chronicletwo:ps2/src/memcard.cpp:82, 162-172, 177-180, 208. The PC flat-file prefix is the same string without the directory: chronicletwo:port/src/save_slots.cpp:36.
- `CSaveData` has no `PORT_RECORD_ASSERT`; it is a "host image" in the port's records inventory, meaning the PC writes and reads its own images in host layout. chronicletwo:ps2/include/savedata.hpp:504; chronicletwo:docs/port/records.md (rows for `SAVEDATA_FORMAT`, `CSaveData`, `CInventUserData`, `CUserDataManager`, `USER_PICTURE_INFO`).
- `CSaveData` member offsets (PS2, computed): `bit_flag` 0x000 (64 words, 2048 flags); `short_flag` 0x100 (128 s16); `map_flag` 0x200 (256 × `CMapFlagData`, 16 bytes each); `unk_1200` 0x1200 (0x800 bytes, unnamed); `play_time` 0x1A00 (s64, frames); `game_progress` 0x1A08; `time_stop` 0x1A0C; `now_time` 0x1A10 (float, hours); `day` 0x1A14; `map_no` 0x1A18; `sub_map_no` 0x1A1A; `prev_map_no` 0x1A1C; `prev_sub_map_no` 0x1A1E; `area_no` 0x1A20; `build_parts_num` 0x1A24 (256 s16, capped at 9999); `edit_data` 0x1C24 (5 × 0x5510); `config` 0x1C574 (0x40); `save_dungeon` 0x1C5B4 (0xCE4); `unk_1D298` 0x1D298; `user_data` 0x1D2A0 (0x457A0); `quest_data` 0x62A40 (0x480); `monster_book` 0x62EC0 (0x1200); `menu_system_data` 0x640C0 (0x308); `bit_ctrl` 0x643C8; `skip_load_bgm` 0x643C9; `tour` 0x643D0 (0x1C); `unk_643EC` 0x643EC (0x1544). Total 0x65930. chronicletwo:ps2/include/savedata.hpp:214-243. Offset names in the header match the computed positions, which supports the calculation.
- `CUserDataManager` (0x457A0, relative offsets): `used_data[150]` +0x0 (inventory, `CGameDataUsed` 0x6C each); `chara_data[2]` +0x3F48 (Max and Monica, `CHARA_DATA` 0x38C each); `robo_data` +0x4660 (0x220); `esa[2]` +0x4880 (bait); `aquarium` +0x4958 (0x530); `monster_box` +0x4EB0 (64 badges, 0x2F00); `party_chara[32]` +0x7DB0 (0xC each); `invent_data` +0x7F30 (0x3CE60); `party_member` u16 +0x44D90; `chara_change` u16 +0x44D92; `active_chr_no` s16 +0x44D96; `monster_id` s16 +0x44D98; `money` int +0x44D9C (capped at 999999); `yarikomi_medal` s16 +0x44DA0 (capped at 999); `special_item_bought` +0x44DC0; `photo_subject[0x200]` +0x44DD0; `last_refresh_time` s64 +0x451D8; `npc_refresh_day` +0x451E0; `fish_tournament` +0x451E8 (0x70); `fish_record` +0x45258 (0x340); `costume_bit` (unsigned long) +0x45598. chronicletwo:ps2/include/userdata.hpp:1150-1181, 2180; money cap at chronicletwo:ps2/include/userdata.hpp:1168 and the add function chronicletwo:ps2/src/userdata.cpp:4662.
- Inventory size depends on a flag: the main item board is 0x8A slots, or 0x90 when `SAVE_FLAG_ITEM_BOARD_EXPANDED` (0xFE) is set; `GetItemBoardMaxNum(ITEM_BOARD_ALL)` is 150 either way, so the overflow area is 12 or 6 slots. chronicletwo:ps2/src/userdata.cpp:3387-3407; chronicletwo:ps2/include/savedata.hpp:123.
- Weapons are `CGameDataUsed` entries (0x6C bytes: `used_type` s16, `item_no` s16, `item_type` s8, `rename_flag` s8, then a union at +0x10). The `WEAPON_USED` union member (0x5C bytes, unverified) holds the durability and absorption gauges, `level` (up to 99), `status[2]`, `attribute[8]`, `special` bits, `fusion_point`, and `name[0x20]`. Equipped gear is stored as copies inside `CHARA_DATA::equip[5]` (+0x170 within `CHARA_DATA` (unverified)), not as indices. chronicletwo:ps2/include/gamedata.hpp:560-700 (union and structs), chronicletwo:ps2/include/userdata.hpp:228-250.
- Party: `PARTY_CHARA_STATUS` bits are IN_PARTY 0x1, JOINED 0x2, IN_HOUSE 0x4, JOIN 0x80 (a request). `party_member` and `chara_change` are 16-bit masks documented as "bits by USER_CHARA"; the exact bit mapping was not traced. chronicletwo:ps2/include/userdata.hpp:124-129, 1161-1162.
- Georama: each of the 5 towns has a `CEditData` (0x5510 bytes): `save_count`, `culture_point`, `parts[300]` (0x24 each), `house[32]` (0x10 each), `place_log[0x800]`, `grid[0x400]` (river cells), `analyze` (0xD0), and 0x400 unnamed bytes. chronicletwo:ps2/include/editdata.hpp:56-84, 440-460; chronicletwo:ps2/include/savedata.hpp:60 (`SAVE_EDIT_DATA_MAX` 5); the parts-stock array `build_parts_num` is capped at 9999 per part (chronicletwo:ps2/src/savedata.cpp:111-126).
- Story flags: `SAVE_BIT_FLAG` values include `SAVE_FLAG_FINNY_FRENZY_UNLOCKED` 0x1A8, `SAVE_FLAG_SPHEDA_UNLOCKED` 0x13D, `SAVE_FLAG_FISHING_CONTEST_UNLOCKED` 0x158, `SAVE_FLAG_COSTUME_UNLOCK` 0x31F, `SAVE_FLAG_CHAPTER_8` 0x2E0, `SAVE_FLAG_CHAPTER_8_STARTED` 0x320, and the world-map layout flags 0x258, 0x268, 0x280, 0x2BC. `SAVE_SHORT_FLAG` holds the fishing tournament count (0x15) and per-class race wins (0x16-0x19). chronicletwo:ps2/include/savedata.hpp:110-149.
- Dungeons: `CSaveDataDungeon` (0xCE4): `stage_id`, `floor_id[7]`, `prev_floor_id[7]`, and `floor_info[162]` records of 0x14 bytes, with per-dungeon floor counts 9, 16, 25, 21, 23, 29, 39. Floor flags are `DNG_FLOOR_FLAG_*` (OPEN 0x1, CLEAR 0x2, and others). A new game opens floors 0 and 1 of each dungeon: floor 0 gets `visit_count` 1 and flag 3 (OPEN and CLEAR), floor 1 gets flag 1 (OPEN). chronicletwo:ps2/include/savedatadungeon.hpp:20-104; chronicletwo:ps2/src/savedatadungeon.cpp:11-62 (`limmit_table` at line 13; `Initialize` at 35-62).
- Fishing tournament schedule: `SAVE_TOUR_INFO` (0x1C): `start_day`, `finish_day`, `now_event`, `type`, `count`, `base_day` (-1 when unavailable). The cycle is 10 days with a 3-day window. `CheckTourBoot` advances the kind by one each cycle: before Finny Frenzy is unlocked the next kind is 1 (or 0 until the contest unlocks); after it, the kind cycles through 1 and 2. Kind 1 clears the tournament's fish records and kind 2 clears aquarium fatigue. chronicletwo:ps2/include/savedata.hpp:62-75, 196-207; chronicletwo:ps2/src/savedata.cpp:201-280. On load, a schedule with `base_day <= 0` and the contest unlocked is set to 7. chronicletwo:ps2/src/memcard.cpp:1345-1350; chronicletwo:port/src/memcard.cpp:215-217.
- Era and chapter: there is no explicit era field. The closest fields are `game_progress` (an index into a table of up to 0x100 story points, each with `chapter` and `section`; chronicletwo:ps2/include/vlgr_info.hpp:23, 44-49) and `map_no` with its map type (`MAP_TYPE_FUTURE` 5, `MAP_TYPE_FUTURE_INTERIOR` 6, `MAP_TYPE_GEORAMA` 1, `MAP_TYPE_INTERIOR` 4; chronicletwo:ps2/include/mapselect.hpp:44-48). `GetGameChapter(game_progress)` returns the chapter (chronicletwo:ps2/src/vlgr_info.cpp:874-882).
- Play time is `CSaveData::play_time`, a count of ticks. It increments in the vsync callback while `PlayTimeCountFlag` is set (chronicletwo:ps2/src/mainloop.cpp:424-437). The retail menus divide by 50 per second (refs/ChronicleTwo/ps2/re/docs/memcard/notes.md:107-109; chronicletwo:port/src/menu_save.cpp:416 divides by 50*60).
- Check digits: `MakeCheckDigit(0, data, size)` sums `(u8)byte % 255` over the bytes at offsets 0, 64, 128, ... (`size / 64` samples). Two digits: `check_digit_half` over `sizeof(CSaveData) / 2` and `check_digit` over `sizeof(CSaveData)`. Only `CSaveData` is covered, never the header. chronicletwo:ps2/src/memcard.cpp:185-200; chronicletwo:ps2/src/memcard.cpp:1081-1083; chronicletwo:port/src/memcard.cpp:19-26, 145-146.
- A zero digit means "not checked": retail and port both skip the comparison when the stored digit is 0. chronicletwo:ps2/src/memcard.cpp:1305-1319; chronicletwo:port/src/save_slots.cpp:375-376.
- Load validation on PS2: version must be `dc2Ver4` or `dc2Ver2` (Ver2 skips digits and runs `TranslateInventUserData`); any other version is "bad". chronicletwo:ps2/src/memcard.cpp:1302-1340.
- Retail save order: `incomplete` is set to 1 in the image before the write, then seeked to +0x45 and cleared with a one-byte write after the data is down. The retail file list (`GetSaveFileInfoFromMc`) rejects a nonzero `incomplete`; the retail load path (`LoadFromMc`) does not check it. The PC `SaveSlotRead` checks it on both list and load. chronicletwo:ps2/src/memcard.cpp:1048, 1161-1162, 2406; refs/ChronicleTwo/ps2/re/docs/memcard/notes.md:97-98.
- The PC port replaces the whole save path: `SaveToMc` builds a complete image with `incomplete` zero and publishes it in one step. chronicletwo:port/src/memcard.cpp:107-191. `LoadFromMc` validates through `SaveSlotRead` before any live state changes. chronicletwo:port/src/memcard.cpp:193-216.
- Publication is atomic on both platforms: `FilesWrite` writes a temporary file beside the target, flushes it, then moves it onto the target with write-through (Windows `MoveFileExW`, `Commit` at files.cpp:69-75) or a directory sync (POSIX, files.cpp:190). A failed write keeps the old file. `FilesWrite` itself is at kazarov:src/cpp/platform/files.cpp:277; kazarov:include/platform/files.hpp:12-18 (the header comment).
- PC catalog: flat files are `<save root>/saves/BESCES-51190dkcl<N>` (N is the save number; a `.card2` suffix marks the second card). Numbers are assigned from the lowest free value. chronicletwo:port/src/save_slots.cpp:36-37, 275-292. Only names that match the exact pattern are listed, so temporary files are ignored. chronicletwo:port/src/save_slots.cpp:294-315.
- Legacy card directories (`mc0`, `mc1` under the save root, written by the libmc shim) are imported on scan: each is copied to a flat file, then moved into `imported/mc0` or `imported/mc1`. Identical copies are not duplicated. chronicletwo:port/src/save_slots.cpp:221-273, 382-495; kazarov:src/cpp/sce/libmc.cpp:19-30, 130-150.
- The catalog's header read (`ReadHeader`) checks the size, version and `incomplete` flag, and reads `play_time` and `game_progress`. It does not check the digits. Digits are checked only on load. chronicletwo:port/src/save_slots.cpp:142-179; the test `ListingDefersChecksumValidationUntilLoad` confirms it. chronicletwo:port/src/tests/save_slots_test.cpp:478-486.
- A PC image is not PS2-compatible. The PC `USER_PICTURE_INFO` holds `char *image` (chronicletwo:ps2/include/userdata.hpp:792), which is 8 bytes on a 64-bit host, so the photo array grows by 30 × 8 = 240 bytes and every later field in `CInventUserData`, `CUserDataManager` and `CSaveData` moves. Inference, not built: PC `CSaveData` about 0x65A20 bytes and `SAVEDATA_FORMAT` about 0x65AB0 bytes (unverified). A PS2 card image has size 0x659C0 and fails the PC size check (`WrongSize`). chronicletwo:port/src/save_slots.cpp:142-146, 347-352; chronicletwo:docs/port/records.md (notes section: "PS2 card images do not load on PC").
- Retail's `dc2Ver2` conversion copies the first two shorts of 128 old 12-byte invention records (`INVENT_CREATED_ITEM_OLD`) into the 4-byte `created_item` array. chronicletwo:ps2/src/inventmn.cpp:1179-1206. The test writes 1536 bytes starting at `created_item`, which spans past the 1024-byte array into `scoop`. chronicletwo:port/src/tests/save_slots_test.cpp:531-562.
- Unlock and debug state comes from header fields that the check digits do not cover: `debug_code` (+0x18) turns on master debug mode (chronicletwo:ps2/src/title.cpp:2282; chronicletwo:port/src/memcard.cpp:97-105), `omake_flag` (+0x46) enables the fish race, the dungeon extra and the costume extra (chronicletwo:ps2/include/title.hpp:243-245), and `costume_bit` (+0x10) is copied from the live costume bits when the costume flag is set (chronicletwo:ps2/src/memcard.cpp:1040-1045).
- The bonus file (`CSubGameData`, 0x5470 bytes) is separate from the main save. Its first byte is `incomplete`, `play_enable` is a u32 at +8, and it holds the Spheda table (`CSphidaData`, 0x1848) and the Finny Frenzy roster (`CGyoRaceData`, 0x2C28). chronicletwo:ps2/include/savedata.hpp:742-809. It is written through the libmc path and is not in the flat catalog. Its `incomplete` byte is written but never checked on load. chronicletwo:ps2/src/memcard.cpp:1776, 1847, 1974-1980 (the only load-side check is the transferred size).
- The album (`CDC2AlbumData`, 0x64CB0 bytes, with `digit_data` covering the photo records) uses its own pair of digits, both computed the same way. chronicletwo:ps2/src/memcard.cpp:21-28, 1391-1392, 1595.
- Path identity is process-global. `GameSetIdentity` calls `PathsConfigure` with `app_dir` "chronicletwo", `DC2_DATA` and `DC2_SAVE` environment names, and sets the settings prefix to "DC2". chronicletwo:port/src/identity.cpp:6-12. `PathsSetSaveRoot` replaces the save root for the whole process. kazarov:src/cpp/platform/paths.cpp:193-196; kazarov:include/platform/paths.hpp:45-49.
- The tick rate defaults to 60 Hz, not the PAL 50 Hz the menus assume. kazarov:include/platform/settings.hpp:50; the tick callback is installed at chronicletwo:port/src/main.cpp:307.

## How it works

Save (PC): the port's `SaveToMc` (chronicletwo:port/src/memcard.cpp:107) clears a `SAVEDATA_FORMAT`, writes `dc2Ver4`, copies the live `CSaveData` (via `GetSaveData()`) into `save_data`, sets the costume and omake fields from the live state (`debug_code` stays zero, as the image was cleared), sets `dng_tree_flag`, takes `unique_counter` as the newest published counter plus one, fills the header copies (`progress`, `fish_num`, `program_loop_no`, `map_no`, dungeon and floor), computes both digits over the copied `CSaveData`, and then publishes through `SaveSlotWrite` (flat file, no-replace for a new save, replace for an existing flat file, otherwise a new flat file followed by archiving the legacy entry). After publication it rescans the catalog.

Load (PC): `LoadFromMc` (chronicletwo:port/src/memcard.cpp:193) reads the chosen catalog row through `SaveSlotRead`, which requires the exact file size, a known version, `incomplete == 0`, and, for each nonzero stored digit, a matching computed digit (zero digits and Ver2 images skip the check). Only then does it `memcpy` `save_data` into the live `CSaveData`. For `dc2Ver2` it runs `TranslateInventUserData`. It copies the load-side header values into `load_*`, and it sets the tournament base day to 7 when that is 0 or less and the contest is unlocked.

Retail flow: the same steps run through `CMemoryCardManager::Step` (chronicletwo:ps2/src/memcard.cpp:500) with libmc's asynchronous commands. Retail writes the `incomplete` byte first, then clears it at +0x45 after the data is flushed. The retail file list (`GetSaveFileInfoFromMc`, chronicletwo:ps2/src/memcard.cpp:2286-2430) rejects a file with `incomplete` set or a version other than `dc2Ver4`.

Catalog (PC): `SaveSlotScan` (chronicletwo:port/src/save_slots.cpp:382) lists flat files, imports legacy card directories, and builds `SaveSlots`. Each entry carries the header fields the menus show (`SAVEDATA_INFO`, chronicletwo:ps2/include/memcard.hpp:206-220). Header metadata for `dc2Ver2` is ignored until conversion (chronicletwo:port/src/save_slots.cpp:170-176). Header reads are cached by path, size and mtime; publication invalidates the cache.

Digests in practice: a digest of 1/64 of the bytes detects some but not all corruption; a single flipped byte at an unsampled offset passes. Because the digest is a sum of `byte % 255` over samples, reordering or swapping sampled bytes can also pass. A file whose stored digest is 0 is not checked at all.

Bonus file: `SaveOamkeFile` and `LoadOmakeFile` (chronicletwo:ps2/src/memcard.cpp:1679, 1880) write and read `CSubGameData` through the libmc path. The port does not override them, so they run retail code on the libmc shim, which maps card port 0 to the `mc0` directory under the save root (inference from the shim and `CardRoot`; a runtime check is still needed).

## Ixion hooks

1. Bundle write seam. The DC2 engine has no save-to-path routine: `SaveToMc` always writes into `SaveSlotsRoot()`. The public functions `SaveSlotWrite(path, image, replace)` and `SaveSlotRead(path, image)` (chronicletwo:port/src/save_slots.hpp:47-55) take a path and do not touch the catalog (`SaveSlots`); the write only erases that path's entry in `header_cache` (chronicletwo:port/src/save_slots.cpp:497-503). Ixion can build the image with the same header code as `SaveToMc` and write it into a bundle folder. This matches the design requirement that each engine's save routine accept a bundle path (ixion:docs/DESIGN.md:139-142; ixion:docs/DESIGN.md:376, open item 10). The better fix is to split the image-building part of `SaveToMc` into a function that fills a `SAVEDATA_FORMAT` from the live state, so the bundle and the native save share one code path.
2. Bundle apply. Replace any raw `memcpy` of the image with `SaveSlotRead` (validation first), then the same post-load steps as `LoadFromMc`: `load_*` fields, the Ver2 translation, and the tournament base-day fix. Skipping the base-day fix would change fishing schedules after transfer.
3. Manifest integrity. Do not rely on the native digests. Hash the whole image bytes in the manifest, since the digests cover only `CSaveData`, sample 1/64 of its bytes, and skip the header.
4. Reading game state: read `CSaveData` and its nested structs, not the header copies. Useful fields: `user_data.money` (+0x44D9C), `party_member` and `chara_data[0..1]` (Max, Monica), `used_data[0..149]` (inventory and weapons), `robo_data`, `monster_box`, `edit_data[0..4]` (Georama towns), `map_no`, `sub_map_no`, `save_dungeon.floor_info` (via `GetFloorInfoPtr`), `bit_flag` and `short_flag` through `GetBitFlag` and `GetShortFlag`, and `map_flag` through `GetMapFlag`. These all come from `chronicletwo:ps2/include/savedata.hpp` and `userdata.hpp` and are host-layout on PC.
5. Era gating: use `game_progress` with `GetGameChapter` for the chapter, and `map_no`'s map type (`MAP_TYPE_FUTURE` and the Georama and interior types) for the era of the current place. This is the closest DC2 has to an era field.
6. Visited places and floors: `map_flag` (per map, 128 flags), `floor_info[*].visit_count` and `flag` (`DNG_FLOOR_FLAG_OPEN`, `DNG_FLOOR_FLAG_CLEAR`), and the story flags in `bit_flag`. `CMapFlagData::GetFlag` is at chronicletwo:ps2/src/map.cpp:59.
7. Playtime: `play_time` is in ticks. If Ixion needs a real duration, it must convert with the tick rate (60 Hz default) and not the 50 Hz the menu displays assume. Do not let a bundle's `play_time` count against Ixion's own clock.
8. Native saves stay untouched. The flat-file writer is only reached from `SaveToMc`, so calling `SaveSlotWrite` with a bundle path does not change the native catalog. `SaveSlots` and `SaveSlotNew` are globals that Ixion should not touch.
9. Route bonus data separately. `CSubGameData` is a separate image with its own `incomplete` byte at +0. Ixion should either carry it in the bundle through `GetSubGameSaveData()` or leave it out and say so.

## Risks and blockers

- Layout split. PC images are host layout and PS2 retail images are PS2 layout. A retail DC2 card cannot be read by the PC port (size check), and a PC image cannot be read on PS2. Converting retail saves needs a layout-aware reader for the pointer field in `USER_PICTURE_INFO`. Inference: the PC image is about 240 bytes larger, plus any alignment changes.
- One identity per process. `GameSetIdentity` sets process-wide paths, settings prefix and window identity (chronicletwo:port/src/identity.cpp:6-12). `PathsSetSaveRoot` is also process-wide. A merged Ixion binary cannot give DC2 and DC1 different identities without changing these globals. A bundle root set with `PathsSetSaveRoot` would redirect DC2's native catalog as well.
- Process-global singletons in the DC2 save code: `SaveSlots`, `SaveSlotNew`, `import_hook` and `header_cache` (chronicletwo:port/src/save_slots.cpp:32-38, 140) and `active_manager` and `dungeon_tree_flag` (chronicletwo:port/src/memcard.cpp:16-17). Two DC2 engines in one process would share them.
- Weak integrity. Digests sample 1/64 of `CSaveData`, skip the header, and are skipped when zero. `debug_code`, `omake_flag` and `costume_bit` are unprotected and can turn on debug mode or unlock content (chronicletwo:ps2/src/title.cpp:2282).
- Listing and loading disagree. The list shows a file with bad digits as Ready, and the load then fails (test at chronicletwo:port/src/tests/save_slots_test.cpp:478-486). Any Ixion UI that lists bundles must validate before it shows them as complete.
- The `dc2Ver2` conversion may overlap `scoop` data. The retail conversion reads 128 × 12 bytes from `created_item` (PS2 offset 0x6D8 in `CInventUserData`). That region ends at 0xCD8, which is 512 bytes into `scoop` (0xAD8 to 0xCD8). The conversion (chronicletwo:ps2/src/inventmn.cpp:1195-1205) reads 128 old records of 12 bytes, which is 1536 bytes from `created_item` and therefore 512 bytes past its 1024-byte end, but it writes only the 128 new 4-byte entries (512 bytes) into the new `created_item`; it never writes `scoop`. The real risk is that the 512 bytes read past 0xAD8 hold whatever the Ver2 layout had there, not invention records. Inference. The test writes and checks only the `created_item` side. Verify against the Ver2 layout before relying on Ver2 data.
- Bonus file load does not check `incomplete`. chronicletwo:ps2/src/memcard.cpp:1974-1980. A half-written bonus file loads as if complete (inference from the code shown; not reproduced).
- Play-time rate. Ticks run at 60 Hz by default on PC, while the display divides by 50 per second (chronicletwo:port/src/menu_save.cpp:416). The retail dungeon timer applies a 6/5 factor (chronicletwo:ps2/src/dngfloor.cpp:572), which may be a compensation for this. The purpose is not verified.
- Minor code hazards in the save code: `CSphidaData::GetHorlScore` indexes `hole_score` with any slot below -1 (chronicletwo:ps2/src/savedata.cpp:338-353); `CSaveDataDungeon::SetFloorID` does not check `stage_id` (chronicletwo:ps2/src/savedatadungeon.cpp:64-68); `MakeMemoryCardFileName` calls `sprintf` with the destination as the format string (chronicletwo:ps2/src/memcard.cpp:162-172). These are retail code. Check whether the PC build reaches them.
- Size: a save is about 0x65930 bytes of game state plus about 240 KB of photo pixels inside `CInventUserData`. Per-engine bundle files are large; per-save copies add up quickly.

## Open questions
