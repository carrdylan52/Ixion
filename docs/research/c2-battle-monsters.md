# ChronicleTwo (DC2): combat and monsters

## What this covers

How Dark Chronicle's dungeon combat resolves in the retail code: named attack rows and the collision primitives that carry them, the hit test, the damage the controlled party member takes, the damage a monster takes, monster statuses, the monster runtime (kind table, slots, placement, targeting), the monster form that Monica turns into through a badge, and the rewards and wear that follow a kill. It ends with what a DC1 character or a DC1 monster would need in order to fight inside DC2, and where Ixion could hook in.

Source scope: `ps2/src` and `ps2/include` in the ChronicleTwo checkout (branch `ixion` off master f44a756). `port/src` was checked for every `PORT_OVERRIDE` that touches combat. Table statistics were produced by parsing the initializers of `Damage_Param_Table` (115 rows), `base_monster_define` (343 named kinds plus a sentinel) and `mos_henge_param` (57 rows) with a read-only script; the numbers below come from that parse. The extracted PAL data was not needed for any claim here.

Not covered: the Ridepod's combat in depth (only its HP drain and defence are noted), fishing and the Spheda sub-game, the monster script bytecode (data, not code), and the time-of-day weapon logic beyond what `RefreshParamater` touches.

Line numbers refer to the checkout named above. Inference is labelled as inference. The DC1 comparison leans on `ixion/docs/research/c1-battle-monsters.md` only where a contrast is useful.

## Key facts

- The combat logic is retail code. `CActionChara::CheckDamage`, `CMonsterMan::CheckDamage`, `CColPrim::IsHit`, `CColPrimMan::CheckHit` and the 115-row table all compile from `ps2/src` with no override (chronicletwo:ps2/src/actionchara.cpp:2940; chronicletwo:ps2/src/monster.cpp:1963; chronicletwo:ps2/src/colprim.cpp:21, 993, 1247).
- The combat-adjacent `PORT_OVERRIDE`s are presentation or setup only: damage numbers (chronicletwo:port/src/dng_damage.cpp:48-167), enemy life gauge, lock-on brackets and name bubbles (chronicletwo:port/src/dng_target.cpp:111-261), lock-on draw (chronicletwo:port/src/dng_hud.cpp:74), the eye-view wrapper (chronicletwo:port/src/dungeon_eye.cpp:8), and monster file loading with widened script stacks (chronicletwo:port/src/dng_event.cpp:12-82; chronicletwo:port/src/monster_memory.hpp:1-5).
- Per-frame order in the dungeon step: monster think, which spawns monster attack primitives (chronicletwo:ps2/src/dng_main.cpp:1981); then `ColPrimMan.Step` (line 2049); then the controlled character's `CheckDamage` (line 2054); then the monsters' `CheckDamage` (line 2059). A monster attack spawned in `ThinkHost` is stepped and tested in the same frame.
- Only one scene character is tested against player-side primitives: the controlled character in scene slot 0 (`CheckHit(0)`, chronicletwo:ps2/src/actionchara.cpp:2976; the only caller of `CActionChara::CheckDamage` is chronicletwo:ps2/src/dng_main.cpp:2054). Other party members in slots 1-7 never take hits.
- Scene slots: party 0-7 (type PLAYER), events 8-23, monsters 24-47 (chronicletwo:ps2/include/dng_main.hpp:61-65; chronicletwo:ps2/include/scene.hpp:91-94).
- The primitive pool is fixed at 64 (`COLPRIM_MAX`, chronicletwo:ps2/include/colprim.hpp:25), shared by party attacks, monster attacks, effect scripts and bullets. `GetPrim` returns the lowest free index or NULL (chronicletwo:ps2/src/colprim.cpp:1209-1218). Callers skip silently (chronicletwo:ps2/src/actionchara.cpp:3419-3423; chronicletwo:ps2/src/monster.cpp:2826-2828).
- `DAMAGE_PARAM` is 0x48 bytes; the name field is 16 bytes, so a row key is at most 15 bytes of Shift-JIS (chronicletwo:ps2/include/colprim.hpp:131-158; `STATIC_ASSERT` on the size). The table holds 115 rows (`DAMAGE_PARAM_MAX`, colprim.hpp:27).
- Table statistics (parsed from the initializer): kinds are monster 76, item and explosion 16, Max melee 5, ridepod gun 4, Monica melee 3, Max gun 3, ridepod punch 2, contact check 2, laser 1, Monica magic 1, ridepod sword 1, grenade 1. No row uses the `RIDEPOD_OTHER` or `MONSTER_OTHER` fallback kinds.
- Shapes: 91 point-only, 13 point with trail, 5 line-only, 5 line with trail, and one row (index 104, kind monster) with no shape bit. That row can never hit (parsed; the `IsHit` shape tests fall through).
- Targets: 108 rows are `DAMAGE_TARGET_BY_OWNER` (owner 0 hurts monsters, any other owner hurts the party); 7 rows (indices 8, 18, 41, 52, 69, 97, 113) hurt both sides (chronicletwo:ps2/src/colprim.cpp:915-922).
- Base damage is zero in 96 of 115 rows. The 19 nonzero rows are 15 item and explosion rows, two Monica or Max gun rows (indices 50, 51, base 6), and two monster rows (indices 41 and 69, bases 50 and 15). Ratio rows (status 0x1000) read their base as a percentage of max HP. Monster attacks take their damage from the monster at spawn time, not from the row (chronicletwo:ps2/src/monster.cpp:2830).
- Hit counts: 105 rows use 1 hit; five rows (indices 5, 17, 27, 101, 105) use 4; one uses 3 and four use 2. No row has a zero hit count, so the monster division `status_chance / hit_count` is safe (parsed).
- Critical rate is zero in 63 rows and otherwise 5-100. Stagger is 1 (71 rows), 2 (31), 3 (6) or 0 (7). Stun frames are 10 (76 rows), 15 (21), 0 (10), 45 (3) and smaller values for the rest (parsed).
- Special status bits used by rows: ratio (0x1000, 8 rows plus several item rows), stone (0x8000), slow (0x10000), curse (0x20000), dry (0x100000, 7 rows), badge drop (0x80000, rows 35, 36, 49), half HP (0x2000, row 73), and one row with 0x4000 that has no named bit in `WEAPON_SPECIAL_FLAG` (row 93) (chronicletwo:ps2/include/gamedata.hpp:46-66).
- Lookup is by name with `strcmp` over the table; a name that is not in the table is a silent no-op. `SetDamage` returns false and does not activate the primitive, and no caller checks the result (chronicletwo:ps2/src/colprim.cpp:893-931; chronicletwo:ps2/src/actionchara.cpp:256-340; chronicletwo:ps2/src/effscript.cpp:5122-5142).
- `SetDamage` copies the row's element and status values and sets `attacker` to -1 and `range` to 10000. A range of 10000 disables the distance falloff for most rows (chronicletwo:ps2/src/colprim.cpp:893-931).
- Hit test: a point primitive hits a hit-group entry when the distance is at most 2 x (primitive radius + entry size); a line primitive uses the distance from the segment (chronicletwo:ps2/src/colprim.cpp:1070-1100). The factor of 2 applies to both sizes together.
- Hit-group entries come from model data: `OBJECT_NAME2` registers up to 24 entries per character, each with a group (2 = hit, 4 = body, 3 = damage span) and a size (chronicletwo:ps2/src/character.cpp:2235-2292; chronicletwo:ps2/include/character.hpp:27, 236-257).
- `hit_mask` records the characters a non-multi-hit primitive has already struck (chronicletwo:ps2/src/colprim.cpp:1020, 1102). The mask is `u64` on the PC port (chronicletwo:port/include/port.h:25-28). The bit is set with `1 << chara_id`, an `int` shift, so ids of 32 and above are undefined in C++ (see Risks).
- `CheckHit` returns the first primitive that hits a given character, so only one primitive can deal damage to a character in one frame; overlapping primitives wait for a later frame (chronicletwo:ps2/src/colprim.cpp:1247-1255).
- Party damage (`CActionChara::CheckDamage`): the function returns early while `damage_time` or `muteki_time` runs (chronicletwo:ps2/src/actionchara.cpp:2967-2972). Base damage is `hit->damage * (1 + fRand(0.15))`, minus defence, divided by the row's hit count, plus `1 + fRand(2)` (lines 2988-2999). A fully defended hit still does 1 to 3 damage.
- Ratio rows take `max_hp * 0.01 * hit->damage` and never kill (the result is clamped to HP minus 1). Half-HP rows take half of current HP with integer division and a floor of 1 (chronicletwo:ps2/src/actionchara.cpp:3001-3011).
- Guard on the party multiplies damage by `0.01 * param->critical_rate` (chronicletwo:ps2/src/actionchara.cpp:3024). The same field is the guard scale for monsters (chronicletwo:ps2/src/monster.cpp:2257-2259). `IGNORE_GUARD` cancels a guard (actionchara.cpp:3027; monster.cpp:2254).
- Display rounding: `GetDispVolumeForFloat` rounds up unless the value is already whole (chronicletwo:ps2/src/menucommon.cpp:1156-1164). Party HP is reduced by `AddHp_Point` (actionchara.cpp:3036).
- Party statuses from hits: poison 30%, slow 30% (not in rain), stone 50%, stop 50%, curse 50%, dry 50%; each has an amulet check through `CheckAmuletAvoid` (chronicletwo:ps2/src/actionchara.cpp:3038-3080, 2874).
- Party reactions: stun is `stun_time x 2` on a guarded hit, `x 3` on the non-knockdown hold branch (not on a stagger, which only adds stagger and sets a 60-frame timer), `x 7` on a knockdown (chronicletwo:ps2/src/actionchara.cpp:3121-3160). A stagger adds the row's stagger value and resets the stagger timer at 60 frames (lines 3183-3190). A lethal hit with Resurrection Powder restores half HP instead (lines 3096-3106).
- Guarded Monica with weapon durability above 30 feeds the hit's elements into her magic sword (chronicletwo:ps2/src/actionchara.cpp:3131-3138; `CBattleCharaInfo::SetMagicSwordPow`).
- Monster damage (`CMonsterMan::CheckDamage`, chronicletwo:ps2/src/monster.cpp:1963-2512): the base is `prim->damage - monster->defense` (line 2051). Ratio rows use max life (2053-2056). Holy-water rows do zero damage unless the monster's `user_mons_id` is 9 (2058-2064). The kind-specific scale is `ext_param[vs_attk_index[kind]]` (2066). Eight element channels add `resist x damage x (element / 127.5)` with a rain table (2070-2080). Two family bonuses x1.2 (2092-2098). Hit-count division (2100). Range falloff (2104-2121). Muteki zeroes damage (2131). Status rolls (2145-2170). HP-cost boost x1.5 with 1% of the attacker's max HP (2173-2179). Critical x1.8 on a 1-in-10 roll (2181-2183). Drain (2185-2195). Steal (2197-2233). Guard (2235-2259). Wear (2261). Life loss (2263).
- Monster reactions: a per-kind table gives the practice bit and the knockback flag (chronicletwo:ps2/src/monster.cpp:499-512). Kind 0x0A (contact check) is ignored (line 2028), and rows with a gift are routed to the gift path (2016-2026).
- Monster hit timing: each damaging hit sets `damage_time = stun_time` (line 2301); the monster ignores all primitives while it is above zero (line 2002). The timer counts down in the action-character step (chronicletwo:ps2/src/actionchara.cpp:3613-3614).
- Monster statuses: poison (0x1), slow (0x2), stop (0x8), stone (0x20) are bits in `MONSTER_STATUS::attr` (chronicletwo:ps2/include/monster.hpp:97-102, 188-196). Stop and stone grey a monster out for 300 and 900 steps; a hit subtracts 90 from the grey timer (monster.cpp:2131-2137, 2140-2166). Slow lasts 1800 steps and halves the monster's step (monster.cpp:2168-2170, 2935-2941).
- Gekirin (rage): `gekirin` falls by `1 / hit_count` per damaging hit; at zero the monster rages for 900 steps at 1.3x attack, but bosses start at -1 and never rage (chronicletwo:ps2/src/monster.cpp:2442-2456; `SetActiveMonster` at 1210-1222).
- Monster-attack primitives: owner is the monster's scene slot (`chara_type = slot + 24`, monster.cpp:1187), so they target the party; the monster's `attack` overrides the row damage each frame (monster.cpp:2828-2830). The spawn and despawn of these primitives happens in `ThinkHost` from the monster's own motion frames (monster.cpp:2815-2838).
- `ThinkHost` skips a monster's script, move and attack spawn when `CheckView` says it is out of sight, but only when it has a target (monster.cpp:2757-2769). `CheckDamage` has no view gate; it tests every live monster (monster.cpp:1993-2014).
- Monster script opcodes: `_SET_DMG2` is the working damage opcode (chronicletwo:ps2/src/runscript_opcodes.cpp:1900-1939). `_SET_DMG` and `_SET_BODY` are stubs that print "NOT FOUND" (runscript_opcodes.cpp:1880-1893; opcode table at 4790-4792). The monster opcode table holds about 170 entries (chronicletwo:ps2/src/runscript_opcodes.cpp:4690-4900).
- Monster kind table: `base_monster_define[344]`, 343 named kinds plus one empty sentinel (chronicletwo:ps2/src/monster.cpp:72-417). The struct is 35 fields and 0xB8 bytes (chronicletwo:ps2/include/gamedata.hpp:1365-1405; size assert at 1405).
- Parsed monster-table statistics: ids run from 0 to 1501 with gaps; 36 kinds are bosses (`boss != 0`); life runs from 1 to 99999; attack from 0 to 198; defence from 0 to 130; 115 kinds have stagger 0; 33 have the no-knock flag (0x4), 15 have the no-stagger flag (0x1); 160 have lift flag 0x1; 231 have a nonzero resist-attr mask; `user_mons_id` takes 11 values (0 to 10) across the kinds; 8 kinds chain to a second kind through `next_id`; 33 kinds share their model (parsed from the table fields).
- Monster status chance is 100 for 306 kinds, 5 for 21, 0 for 15 and 50 for one. Guard rate runs from 0 to 40. Ratio-damage rate is 100 for 244 kinds, 20 for 35, 50 for 28 and 200 for 20.
- Monster runtime limits: 24 active monsters (`MONSTER_ACTIVE_MAX`), 12 loaded kinds (`MONSTER_REFER_MAX`), 32 placement entries (`MONSTER_LOCATE_MAX`) (chronicletwo:ps2/include/monster.hpp:31-36). `CActiveMonster` is 0x14A0 bytes (monster.hpp:371).
- Monster files: model pack `dungeon/monster/<model>.chr` with a config, script `dungeon/monster/<script>.stb`, sound bank `snd2/mon/EN_<n>.snd` (chronicletwo:ps2/src/monster.cpp:1075-1114).
- Floor placement: `dungeon/cfg_file/mos_place<stage>.cfg` lists monster kinds and a parameter per floor entry; the port override reads it and loads each kind (chronicletwo:port/src/dng_event.cpp:59-82). Runtime spawns go through the `_CREATE_MONSTER` opcode, which returns 0 unless the kind is already loaded (chronicletwo:ps2/src/runscript_opcodes.cpp:3673-3690).
- Targeting: monsters are ranked by distance to their target each step (`PriorityLevelCheck`, chronicletwo:ps2/src/monster.cpp:1449-1481). The player locks on by mode: nearest (automatic, default in dungeon setup at chronicletwo:ps2/src/dng_main.cpp:390) or select (cycled with a button) (chronicletwo:ps2/include/scenesnd.hpp:139-142; chronicletwo:ps2/src/actionchara.cpp:3455-3480). Lock-on range is 300 and the nearest range 400 (actionchara.cpp:3462-3474).
- Monster kill: `_SET_DEAD_START` sets the slot dead, spawns a large money orb and five small ones, a badge orb when `drop_badge` is set (item number = the kind's `user_mons_id`), and a one-in-six item drop (chronicletwo:ps2/src/runscript_opcodes.cpp:3184-3300). `_SET_DEAD_OFF` starts the fade and spawns 6 to 16 weapon-experience orbs, each carrying the killer and the damage source (runscript_opcodes.cpp:3344-3470).
- Weapon experience credit (`AddExpWeaponParam`) switches on `chr_no` for 0 to 3 only; a character number outside those cases gets no credit (chronicletwo:ps2/src/maintex.cpp:206-270). The orb is collected at chronicletwo:ps2/src/dng_object.cpp:1632-1643.
- Gift and badge: a gift check needs the Badge Box item (`ITEM_ID_BADGE_BOX`, chronicletwo:ps2/include/gamedata.hpp:112; counted in `CMonsterMan::CheckDamage` at chronicletwo:ps2/src/monster.cpp:1991, not inside `CheckGiftPack`) and a matching gift pack (`CheckGiftPack`, chronicletwo:ps2/src/monster.cpp:1933-1957). A matching gift sets `drop_badge`, so the monster drops its transformation badge on death (monster.cpp:2016-2022). The badge pickup calls `monster_box.EnableChange(item_no)` (chronicletwo:ps2/src/dng_object.cpp:1513-1530).
- Monster form (Monica): `CBattleCharaInfo::SetChrNo` for `USER_CHARA_MONSTER` sets `chara_type = BATTLE_CHARA_MONSTER`, points the badge record at `chara_data.monster`, and leaves `hp` pointing at Monica's health gauge (chronicletwo:ps2/src/userdata.cpp:4812-4866).
- Monster form stats: attack and defence are from `GetAttackVol` and `GetDefenceVol` on the badge (chronicletwo:ps2/src/userdata.cpp:2480-2520). Attack scale is `1 + 2 x level / 98`, capped at 999; defence adds `2 x degree` where degree is `level / 6` capped at 15 (userdata.cpp:2480-2520; `GetDegreeLevel`). Base values come from `mos_henge_param[57]` (chronicletwo:ps2/src/userdata.cpp:68-124; lookup at 2470-2477).
- Monster form drain and badge: the form loses 0.005 badge HP per step, or 0.0025 with badge 12 (`IsChange(0xC)`); badge 11 scales attack and defence by 1.25 (chronicletwo:ps2/src/userdata.cpp:5042-5052; drain applied to the badge gauge at 5770-5772).
- Monster form death: `IsRunDeadEvent` kills the form when the badge gauge reaches 0, and also when Monica's HP reaches 0 (chronicletwo:ps2/src/dng_main.cpp:3015-3033).
- Monster form primitives: `SetDamageParam` for `chr_no == 3` takes only the attack value from the weapon-param path, sets `attacker = 3`, and leaves the row's element and status (chronicletwo:ps2/src/maintex.cpp:160-200). Its element channels are zeroed (userdata.cpp:5058-5068).
- Monster form melee wear hits the badge gauge (`GetNowAccessWHp` returns `chara_data.monster->hp` for the form; chronicletwo:ps2/src/userdata.cpp:5089-5091). `calcWeaponParamWhp` applies wear to melee rows only (chronicletwo:ps2/src/maintex.cpp:94-125).
- Form switching: `ChangeSetUnit` moves between Monica and the form through `CheckQuickChange` (chronicletwo:ps2/src/dng_main.cpp:3039-3070).
- Monster-form allies: while in the form, `IsBattleStyleDist` ignores monsters of the same family (chronicletwo:ps2/src/monster.cpp:830-857), and `CheckMonsterTolk` picks only unraged, non-boss, same-family monsters (monster.cpp:859-921; its first branch is the debug talk path).
- Monster book: `KillMonsterCount` writes to a book with 0x180 entries (`MONSTER_BOOK_ENTRY_MAX`); kind ids of 384 and above are not recorded (chronicletwo:ps2/include/quest.hpp:22; chronicletwo:ps2/src/quest.cpp:212-221; chronicletwo:ps2/src/userdata.cpp:5952-5967). 63 of the 343 kinds have ids of 384 or above (parsed).

- Element order: fire 0, cold 1, thunder 2, wind 3 (chronicletwo:ps2/include/dng_effect.hpp:66-70). The element arrays hold eight channels, but only four have a name in code; channels 4-7 are used only in arithmetic (monster.cpp:2070-2080; inference from the enum use).

## How it works

### 1. Frame order and ownership

Each dungeon step runs monster behaviour first (`ActiveMonster->ThinkHost`), which fills the primitive pool with monster attacks (chronicletwo:ps2/src/dng_main.cpp:1980-1981). Then every primitive steps (line 2049), the controlled character tests its hits (2054), and the monsters test theirs (2059). Ownership is by scene slot. A primitive's `owner` decides its side only through `DAMAGE_TARGET_BY_OWNER`: owner 0 is the party and hurts monsters; any other owner is a monster and hurts the party (chronicletwo:ps2/src/colprim.cpp:915-922). `IsHit` then filters by the candidate's scene type (colprim.cpp:1001-1014): a party-type target is skipped if the row lacks the PLAYER bit, a monster-type target if it lacks the MONSTER bit.

### 2. Where attack records come from

There are three sources. Each ends in a `CColPrim` from the pool.

- Motion-driven entries. A character or monster holds up to 11 `ACTION_DAMAGE` slots (chronicletwo:ps2/include/actionchara.hpp:146, 252). Each names the frames it spans, a radius, a damage row name, a motion and a window in ratio units. `EntryDamage2` fills a free slot (chronicletwo:ps2/src/actionchara.cpp:256-340). For party characters the action script calls `_SET_DMG2` (chronicletwo:ps2/src/actscript.cpp:992-1020), which doubles the radius and stores a power rate. For monsters the script calls `_SET_DMG2` on the monster (runscript_opcodes.cpp:1900-1939), which takes its radius from the `CHARA_ENTRY_GROUP_DAMAGE` frame size when the given power is zero.
- Per-step spawn. In the party step, each live entry creates its primitive when the motion frame enters the window, copies the row, and calls `SetDamageParam` (party weapon data, slot 0). It deletes the primitive when the frame leaves the window (chronicletwo:ps2/src/actionchara.cpp:3411-3437). In `ThinkHost`, the monster does the same with `SetDamage(name, chara_type)` and the monster's `attack` (chronicletwo:ps2/src/monster.cpp:2814-2838).
- Direct primitives. Machine-gun, laser and magic shots and effect scripts create primitives with `SetDamage` (chronicletwo:ps2/src/actscript.cpp:1500-1530 for Monica's magic, which sets `range = 500` and uses slot 1; `_COLPRIM_CREATE` in chronicletwo:ps2/src/effscript.cpp:5122-5152 with the owner defaulting to the script's user id).

For a party primitive, `SetDamageParam` copies the weapon's attack, the eight element values from `status[2..9]`, and the special bits (with poison kept one time in ten and the 0x8 stop bit one time in twenty). It records `attacker = chr_no` (chronicletwo:ps2/src/maintex.cpp:160-200). A zero durability gauge gives zero attack (`attack[0] <= 0` path, lines 173-175).

### 3. Hit test

`CColPrim::IsHit` (chronicletwo:ps2/src/colprim.cpp:993-1113) runs in this order: the primitive must be active and carry a row; the target must exist; the target's type must match the row's target bits; and a non-multi-hit primitive must not already have the target in `hit_mask`. Then it builds the sample points: for point shapes the current position and, with trail, the midpoint of the move; for line shapes the segment and, with trail, two extra segments. For each active hit-group entry it compares the sample to the entry at 2 x (radius + size). The first match sets `hit_pos` and a normalised `hit_vec` (vertical component zeroed for points) and returns true. It records the hit in `hit_mask` (for non-multi rows) and increments `hit_num`.

`IsReversVec` (colprim.cpp:1115-1135) lets a party attack whose `attacker` is 0 (Max) push another primitive away; the effect scripts read the result through `_COLPRIM_GET_REVCNT` (chronicletwo:ps2/src/effscript.cpp:5319-5333). Monster bullets are deflected only by Max's attacks in this way (inference from the attacker check).

### 4. The party takes a hit

`CActionChara::CheckDamage` (chronicletwo:ps2/src/actionchara.cpp:2940-3205) follows the order in Key facts. It then sets knockback from `hit->hit_vec`, a 4.0 speed and a 5-frame blow timer (lines 3106-3110), and picks a reaction. Guard, stagger, knockdown, hold and death each set `damage_req` or the reaction program. Guard plays a guard effect and charges Monica's magic sword if she is holding the sword with durability above 30. Non-guard hits set the stun timer by reaction (3154-3159).

### 5. A monster takes a hit

`CMonsterMan::CheckDamage` (chronicletwo:ps2/src/monster.cpp:1963) loops over the 24 monster slots. A slot is skipped when it is not live, has `damage_time > 0`, has `MONSTER_ATTRIB_NO_DAMAGE`, or is held (2002-2010). It calls `ColPrimMan.CheckHit(i + 24)` once per slot (2014) and handles the first primitive that hits. Then, in order:

- Gift primitives are handled first (2016-2026).
- The kind is recorded, `react_tbl` finds the practice bit and knockback flag (2028-2046), and the damage is computed as in Key facts (2051-2259).
- A zero result takes the no-damage branch: `no_damage_cnt` is bumped, a guard or no-damage label shows, and the monster skips the reaction (2262-2287).
- Otherwise the blow vector is set unless the monster has `MONSTER_ATTRIB_NO_BLOW` or the reaction has no knockback (2288-2300). `damage_time` is set to the row's stun frames (2301). The hit sound, palette, hit effect and score follow (2302-2405).
- The reaction is picked from the hit flags and state: knockdown, no-stagger, status (greyed), or dead when life reaches zero (2405-2430). A killing hit saves the kind, the attacker, the source and the attribute bits for the reward code (2425-2430).
- Rage counts down on each damaging hit (2442-2456). The reaction sets `req_prog` to the matching program (2458-2503). A knockback or damage hit with the stun flag also sets `MONSTER_PROG_PIYORI` for 120 frames (2505-2508).

### 6. Monster runtime, placement and targeting

`SetActiveMonster` (chronicletwo:ps2/src/monster.cpp:1128-1256) finds a free slot, copies the loaded kind's model (or shares it when the kind's `share_model` is set), and copies the table entry into the monster's own `param`, which the script can change. `life`, `max_life`, reward, `attack`, `defense`, `whp` and gekirin come from the table. Bosses start with gekirin -1 and their own boss life gauge. `chara_type = slot + 24` makes the monster an owner for its primitives. The init program runs at placement.

Each step (`ThinkHost`, monster.cpp:2663-2947) updates the statuses, computes the distance to the target, optionally rolls the murderous escape (monster.cpp:2787-2800, which uses raw `rand()`), runs the script for the requested program, moves the monster (`MoveUnit`), creates or deletes its damage primitives from motion frames, fades dead monsters, and steps the timers. `PriorityLevelCheck` ranks live monsters by target distance each step (monster.cpp:1449-1481). `CheckView` decides sight from the rank and distance (monster.cpp:611-645); a monster that fades out is still tested for damage.

### 7. Kill, rewards and wear

`_SET_DEAD_START` (runscript_opcodes.cpp:3184-3300) sets the state to dead and computes money: reward times 1.0, plus 0.3 for a Wealth bit or an NPC bonus, minus 0.3 for the Less Money bit (3207-3218). It splits the money into one large orb and five small ones (3238-3260). A badge orb is spawned for `drop_badge`, with the item number set to the kind's `user_mons_id` (3270-3277). A one-in-six roll may drop one of the kind's three drop items (3280-3310), and the steal roll on a hit has already cleared the table's drop slots on success (monster.cpp:2197-2233; the table entry is a per-monster copy).

`_SET_DEAD_OFF` (runscript_opcodes.cpp:3344-3470) starts the death effect, sets `dead_alpha` to 128, and scatters 6 to 16 weapon-experience orbs. The count is fixed by `reward_exp` thresholds (below 6, 6 to 49, 50 to 199, 200 to 499, 500 and up); the experience bit scales it by 1.2. Each orb carries the killer's id and the damage source. Collection calls `AddExpWeaponParam` (maintex.cpp:206). The switch runs on the active character first. When the orb's killer differs from the active character, Max and Monica split the credit between their two weapons, while the ridepod and the monster form give the whole amount to their own gauge. When the killer matches, the damage source picks the weapon: melee to the main weapon, guns to the sub weapon, items to both, and ridepod hits to the ridepod gauge (maintex.cpp:206-270).

The fade drops `dead_alpha` by 3 per step. When it reaches zero the monster counts toward the book and the floor's kill count, and a gate key drops if the kind has one (monster.cpp:2839-2866).

Party wear: melee hits on monsters wear the weapon's durability by `monster->whp * 0.5`, reduced by the weapon's durability stat, and scaled by the wear bits (`calcWeaponParamWhp`, maintex.cpp:94-125). The attacker's durability reaching zero triggers `AddAbsRate(0, -0.1)` (maintex.cpp:118-123).

### 8. Monica's monster form

The form is a Monica substitute chosen from the badge box. The badge record (`MOS_CHANGE_PARAM`, 0xBC bytes) carries the chosen monster, its level, its class level, progress, its health gauge (used as the form's life and wear pool) and its absorption gauge; `LevelUp` raises the level when the absorption gauge fills (userdata.cpp:2542-2560). The monster box holds 64 records (`CMonsterBox`, 0x2F00 bytes, userdata.hpp:406-471).

Loading: The character setup routine loads the form's model from the monster's model name and its action script `dungeon/act_script/<model>` into the party's slot 0 part (chronicletwo:ps2/src/charasetup.cpp:344-370). The form therefore runs its own action script with its own named damage rows, and `ChangeSetUnit` switches between Monica and the form (dng_main.cpp:3039-3070).

Stats: attack and defence come from the badge; the form's melee and gun rows come from its own action script. The attack is `GetAttackVol(-1)` times a per-form multiplier (1.25 with badge 11) and is written to the weapon-param slot 0 (userdata.cpp:5042-5068). Element and status channels are zeroed, so the form's hits carry only the row's own element and status. The form's life is Monica's gauge, but the per-step drain (0.005 or 0.0025 per step) and the melee wear both act on the badge gauge (userdata.cpp:5770-5772 and 5089-5091). The form dies when that gauge runs out (dng_main.cpp:3025), and also when Monica's HP runs out (3031-3033, the fall-through check).

The form's stats come from a 57-row table keyed by monster number (`mos_henge_param`, userdata.cpp:68-124). Every form number in `monster_progress_tbl` (menuchr.cpp:7909-7928) has a row (the four numbers without a row, 4 to 7, appear only in the key column). Across the henge rows, base attack ranges from 7 to 100 and base defence from 3 to 60 (parsed).

### 9. Party statuses and the monster-form guard

Party statuses come from the row bits and amulets. Each party status uses a fixed percentage and an amulet check: poison 30% (Antidote), slow 30% (Anti-Goo, not in rain), stone 50% (Anti-Petrify), stop 50% (Non-Stop), curse 50% (Anti-Curse) and dry 50% (chronicletwo:ps2/src/actionchara.cpp:3038-3080). Monster-side statuses use the monster's `status_chance / hit_count` against a roll, with `resist_attr` blocking each bit (monster.cpp:2145-2170).

## Ixion hooks

- `CColPrim::SetDamage` (chronicletwo:ps2/src/colprim.cpp:893) is the single choke point for named rows. An Ixion name map here can translate DC1 attack names to DC2 rows (same kind, same target), and log a miss instead of failing silently. This is the cheapest place to add DC1 attacks without touching any script.
- `CActionChara::EntryDamage2` (actionchara.cpp:256-340) and the `_SET_DMG2` opcodes (actscript.cpp:992; runscript_opcodes.cpp:1900) are where motion-driven attacks enter. A DC1 character's animation events could be routed here if its motions are re-authored as DC2 action scripts.
- `CActionChara::CheckDamage` (actionchara.cpp:2940) applies the party formula. Ixion could branch on a DC1 attacker (`hit->attacker` or the row's `source_type`) to apply DC1 defence or guard semantics for a DC1 character.
- `CMonsterMan::CheckDamage` (monster.cpp:1963) applies the monster formula. A DC1 monster encoded as a `BASE_MONSTER_TBL` row inherits every factor here: `ext_param` per kind, `element_resist`, `status_chance`, `resist_attr`, `guard_rate`, `stagger`, `flags` and the drop slots.
- `CMonsterMan::SetActiveMonster` (monster.cpp:1128) and `EntryRefer` / `LoadReferMonsterFile` (monster.cpp:1034-1127) are the spawn and asset-load points. `_CREATE_MONSTER` (runscript_opcodes.cpp:3673) can place a kind that was preloaded, so a crossing floor could preload DC1 kinds at entry and spawn them from script.
- `CBattleCharaInfo::SetChrNo` (userdata.cpp:4812), `RefreshParamater` (4972) and `SetDamageParam` (maintex.cpp:160) are where a new party type would need a branch. The monster-form branch (`BATTLE_CHARA_MONSTER`) is a template: it reads stats from a table (`GetAttackVol`), drives a badge gauge, and skips the element channels. A DC1 character could ride the same pattern as a new `chr_no` with its own branch.
- `mos_henge_param` and `GetMonsterHengeParam` (userdata.cpp:68, 2470) are the existing injection point for stat sets that come from another game. `ixion:docs/DESIGN.md` (plan item 4 and the Monica row) already points at this path.
- `_SET_DEAD_START` and `_SET_DEAD_OFF` (runscript_opcodes.cpp:3184, 3344) are the reward and drop hooks. Ixion could scale money or weapon experience per source here, and `AddExpWeaponParam` (maintex.cpp:206) is where a new party member's experience would go (its switch has no default).
- `ChangeSetUnit` and `IsRunDeadEvent` (dng_main.cpp:3015, 3039) are the unit-swap and death hooks. Crossing-time party changes and death rules for DC1 characters would live here.
- `CheckGiftPack` and the badge pickup (monster.cpp:1933; dng_object.cpp:1513-1530) show how a kill can unlock a monster for the monster box. An Ixion "recruit" rule could reuse the drop-badge path.
- Floor state: `CMonsterMan::Initialize` (monster.cpp:761) clears all slots and kinds; the port's floor loader calls it with the initialise flag (chronicletwo:port/src/dng_event.cpp:59-66), and the kill count is kept by `NowFloorInfoPtr` and the save-side book (`KillMonsterCount`, userdata.cpp:5952). A time-travel transition that keeps or resets floors would hook here.
- Presentation: `port/src/dng_damage.cpp` and `port/src/dng_target.cpp` are where damage numbers and the enemy gauge are drawn. They keep identity outside the retail structs, so they are safe places to show DC1-style numbers without changing the fight.

## Risks and blockers

- Silent name misses. `SetDamage` returns false and leaves the primitive inactive; `EntryDamage2` and `_SET_DMG2` do not check the name (colprim.cpp:893-931; actionchara.cpp:256-340). A DC1 attack name that is not in the 115-row table does no damage and prints nothing. Verified by reading.
- Name length. Row keys are 16-byte fields holding at most 15 bytes of Shift-JIS (colprim.hpp:132). Monster names are 32 bytes and rejected when longer (`_MONSTER_NAME`, monster.cpp:2947-2962; gamedata.hpp:1369). Model and script base names are 16 bytes (gamedata.hpp:1370-1371).
- Fixed table sizes. `DAMAGE_PARAM_MAX` (115), `base_monster_define[344]` (343 used), `react_tbl[14]`, `vs_attk_index[26]`, `MONSTER_REFER_MAX` (12), `MONSTER_ACTIVE_MAX` (24), `COLPRIM_MAX` (64), `ACTION_DAMAGE_MAX` (11). Adding DC1 content may need these enlarged, and the struct sizes are asserted (`STATIC_ASSERT` at colprim.hpp:153, 318 and 412, and monster.hpp:371 and 731 for the monster class and manager).
- Save layout. `MOS_CHANGE_PARAM` (0xBC), `CMonsterBox` (0x2F00), `CMonsterBook` (0x1200), `CBattleCharaInfo` (0x90) are asserted in the code (userdata.hpp:398, 471, 2624; quest.hpp:211). Adding fields changes save layouts; any DC1 side data must go in a separate record.
- Monster book range. Kinds with ids of 384 or above are not recorded (quest.cpp:217-219). 63 of 343 kinds fall in that range; their kill counts stay zero (parsed; userdata.cpp:5952-5967).
- Party hit test covers slot 0 only (actionchara.cpp:2976; dng_main.cpp:2054). A DC1 party member in another slot would never take a hit unless the loop is extended. Inference: the rest of the party is not in the active fight in retail either.
- One hit per target per frame. `CheckHit` returns the first match (colprim.cpp:1247-1255), and a monster with `damage_time > 0` is not tested at all (monster.cpp:2002). Overlapping primitives land later, not in the same frame. This is by design in retail but matters for any crossing that adds a second attacker.
- Hit-mask shift. `hit_mask |= 1 << chara_id` (colprim.cpp:1102) and `hit_mask & (1 << chara_id)` (colprim.cpp:1020) use an `int` shift. Monster slots 32 to 47 are shifts of 32 or more, which is undefined in C++. On x86 a variable shift masks the count to 5 bits, so slot 32 shares bit 0 with party slot 0 and so on up to slot 47 sharing bits 0 to 15 with party slots 0 to 15 (inference from the compiler's behaviour). Only the 7 two-sided rows can see the collision, so a two-sided row that hits party slot 0 can spare monster slot 32 in the same attack. Slot 31 is also a sign-extension case for the 64-bit mask (inference).
- Double counting of no-damage hits. A zero-damage monster hit increments `no_damage_cnt` twice (monster.cpp:2128 and 2270). Verified by reading both lines; the second is inside the no-damage branch.
- Monster-form HP split. Hits on the form reduce Monica's health gauge (`hp` in `CBattleCharaInfo`), but the form's per-step drain and melee wear act on the badge gauge (userdata.cpp:5770-5772, 5089-5091). The HUD reads Monica's gauge (`GetNowHp_i`, userdata.cpp:5462-5470). Whether the split is intended is not clear from the code (inference: it looks deliberate because death checks both gauges, dng_main.cpp:3025-3033).
- Stale damage slots. `AllDeleteDamage` (actionchara.cpp:341-351) deletes primitives but leaves each slot's `use` flag and its `prim` pointer set. The spawn loop only clears `prim` when the frame leaves the window (3427-3431). A reused primitive index could then be deleted by a stale slot (inference, not reproduced). `use` is only reset by `ResetScript` (actionchara.cpp:121-146), which runs from `_INIT_SCRIPT` (actscript.cpp:315-318), from `InitScript` (actionchara.cpp:3220) and from initialisation (actionchara.cpp:3805). How slots are recycled between attacks is an open question.
- Held-monster cleanup loop. In `ThinkHost` the cleanup for a held monster advances its damage pointer only on used slots (monster.cpp:2730-2740). A gap in the used slots would leave later primitives alive. Inference: the spawn order makes gaps unlikely.
- Gift matching requires all three gift slots to equal the accepted item (monster.cpp:1950-1955). If that is intended, a gift must be three of the same item. Inference: the other gift field in the table is unused.
- Overloaded field. `critical_rate` is documented as a critical percentage (colprim.hpp:143) but is used only as the guard scale for both party and monsters (actionchara.cpp:3024; monster.cpp:2258). A row with critical rate 0 blocks all damage when guarded. Critical hits use a fixed 1.8 and 10% (monster.cpp:2181-2183).
- Element channels. The design table lists five elements with holy as an element (ixion:docs/DESIGN.md crosswalk rows `w_elem` and `w_monster`). In code, holy water is a special status bit (`WEAPON_SPECIAL_HOLY_WATER`, gamedata.hpp:64), and only four channels have names. The DESIGN mapping needs checking against the four named channels.
- Unknown row 0x4000. Row 93 uses status bit 0x4000, which has no named flag in `WEAPON_SPECIAL_FLAG` (gamedata.hpp:46-66). Its effect is unknown from this code (inference: a status bit that nothing checks).
- Debug output on the PC port. `printf` runs on the per-hit path (monster.cpp:2063, 2105, 2119, 2205) and in the death opcode (runscript_opcodes.cpp:3245-3246). These are noise, not correctness problems, but they cost console time in a fight.
- Debug hooks in retail code. `dbinfo.effect_id` and `dbinfo.effect_vol` are read on the normal element path (monster.cpp:2356-2361), and `dbinfo.monster_talk` is read in `CheckMonsterTolk` (monster.cpp:867). All three are zero unless the debug menu sets them (chronicletwo:ps2/src/dng_debug.cpp:112-114, 210-211).
- Port memory budget. `PrepareMonsterMemory` sizes the monster script stacks from a fixed quadword budget (chronicletwo:port/src/dng_event.cpp:12-19). Larger DC1 scripts would need a new budget.

## Open questions

- How are `ACTION_DAMAGE` slots recycled between motions? The spawn loop never clears `use`, and the reset paths found are `_INIT_SCRIPT` and initialisation. A runtime or bytecode check would settle whether a character with more than 11 attacks in one script life stops dealing damage.
- Does any party or monster script call `_SET_DMG`, the stubbed opcode? The scripts are data, so this needs the bytecode or a runtime log.
- Is `user_mons_id == -1` reachable? The struct comment says -1 means none, no table row uses it, but several paths (`IsBattleStyleDist`, `CheckMonsterTolk`) test for it (monster.cpp:836, 890).
- What is the monster-form revert path after a death? `IsRunDeadEvent` sets the death request; the switch back to Monica is not traced here.
- What does `DNG_PAUSE_ENEMY_STEP` do in practice for same-family monsters while the form is out (monster.cpp:2717-2720)? The code steps only same-family monsters under this pause.
- The meaning of the 0x4000 status bit and of element channels 4-7.
- Whether the badge number 11 and 12 bonuses (1.25x and half drain) are the only special badges, and how `get_gajji_id_from_monster_progress_table` maps forms to box records (not traced).
- The Ridepod's damage path and its kinds (11 to 14) beyond the table counts.
- DC1 side (for the crossing): the six-character layout and the 200-plus owner encoding in `ixion/docs/research/c1-battle-monsters.md` do not map onto DC2's four party types or its slot-0-only test. Which DC1 characters become playable in DC2's slot-0 model is a design question, not a code one.
